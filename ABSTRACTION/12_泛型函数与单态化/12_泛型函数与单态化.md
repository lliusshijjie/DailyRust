# 第 12 课 · 泛型函数与单态化

> 所需工具链：rustc 1.85+（edition 2024） ｜ 讲解：本文件 ｜ 独立代码：`12_generics_and_monomorphization.rs`

## 一、底层原理

### 12.1 泛型是"类型参数化"，不是运行时多态

泛型让同一份代码服务多种类型，写法上是在类型/函数/方法上引入**类型参数**：

```rust
fn identity<T>(value: T) -> T { value }

struct Pair<A, B> { first: A, second: B }

enum Either<L, R> { Left(L), Right(R) }
```

它和三种"多态"要区分开：

| 机制 | 例子 | 分发时机 | 代价 |
|---|---|---|---|
| 泛型（单态化） | `fn f<T>(x: T)` | 编译期，每个具体类型一份代码 | 代码体积、编译时间 |
| trait 对象（动态分发） | `&dyn Display` | 运行期 vtable | 一次间接调用、对象大小 |
| 枚举（封闭联合） | `enum E { A(i32), B(String) }` | 编译期 `match` | 最大变体的大小 |

泛型不是"运行时查表"，而是**编译期把 T 替换成具体类型**。这一点决定了它的所有优缺点。

### 12.2 单态化（monomorphization）

编译器会为每个实际使用的具体类型生成一份专门的机器码。示例里：

```rust
identity(7)          // 生成 identity::<i32>
identity("x")        // 生成 identity::<&str>

type_name_of(&1i32)  // "i32"
type_name_of(&"x")   // "&str"
```

`std::any::type_name::<T>()` 在单态化后的函数体里看到的是**具体类型**，这就是
"每个 T 一份实例"的直接证据。

单态化的好处：

- **零运行时开销**：没有 vtable、没有类型擦除、没有向下转型
- 编译器知道具体类型后可以做**内联、常量传播、死代码消除**
- 泛型算法（如 `Iterator::sum`）能和手写循环生成同样高效的代码——"零成本抽象"

单态化的代价：

- **代码体积**：`Vec<i32>`、`Vec<String>`、`Vec<MyType>` 各生成一份相关代码
- **编译时间**：每个具体类型都要重新优化
- **跨 crate 成本**：泛型函数在使用它的 crate 里实例化，需要把 MIR/元数据传给下游

用 `cargo bloat` 可以查看二进制里哪些泛型实例占了大头。类型参数太多、组合太多时，
考虑改用 `dyn Trait`（运行时多态）或枚举分派（第 16 课）。

### 12.3 trait 约束是"定义处检查的契约"

泛型函数只能用**约束允许**的能力：

```rust
fn largest<T: PartialOrd>(values: &[T]) -> Option<&T> {
    let mut largest = values.first()?;
    for value in values {
        if value > largest { largest = value; }   // 需要 T: PartialOrd
    }
    Some(largest)
}
```

少写约束时，错误发生在**函数定义处**（E0369/E0277），而不是调用处。这和 C++ 模板的
"实例化时才报错、错误信息埋在模板展开里"形成鲜明对比。Rust 的约束提前到签名，
错误定位更准。

约束可以写在参数上，也可以用 `where` 子句：

```rust
fn sum<T>(values: &[T]) -> T
where
    T: Copy + std::iter::Sum<T>,
{
    values.iter().copied().sum()
}
```

多个约束用 `+`；`where` 在多参数、长签名时更易读。

### 12.4 `Sized` 与 `?Sized`

类型参数默认隐含 `Sized` 约束（因为要按值传递）：

```rust
fn f<T>(value: T) { }          // T: Sized
fn g<T: ?Sized>(value: &T) { } // 允许 str、[T]、dyn Trait
```

`str`、`[T]`、`dyn Trait` 都是**未定长类型**，只能通过引用/指针使用；
需要接收它们时写 `T: ?Sized`：

```rust
fn size_of<T: ?Sized>(value: &T) -> usize {
    std::mem::size_of_val(value)
}
size_of("abc");                  // 3
size_of(&[1u8, 2, 3][..]);       // 3
```

### 12.5 泛型与所有权、生命周期

- `T` 默认按值传递：需要保留调用方的值就用 `&T`，需要复制就加 `T: Copy`
- 泛型类型可以包含引用：`struct Wrapper<'a, T> { value: &'a T }`
- 生命周期约束：`T: 'a` 表示 `T` 里的借用至少活到 `'a`
- trait 约束可以叠加：`T: Clone + Ord`

### 12.6 泛型结构体、枚举与方法

```rust
impl<A, B> Pair<A, B> { ... }                 // 对所有 A、B
impl<A: Display, B: Display> Pair<A, B> { ... } // 只有可显示时才有的方法
impl Pair<i32, i32> { ... }                   // 特化：只对 i32 对
```

- 约束可以放在 `impl` 上（影响整块方法），也可以放在单个方法上
- 特化 `impl` 让某些方法只对特定类型可用；但**不能**与泛型 impl 定义同名方法
  （会冲突，E0592）
- trait 的"特化"是 nightly 功能，稳定 Rust 里不要依赖

### 12.7 `impl Trait` 与泛型的关系

在**参数位置**，`impl Trait` 是匿名泛型参数的语法糖：

```rust
fn join_all(values: impl IntoIterator<Item = i32>) -> String { ... }
// 约等于
fn join_all<I: IntoIterator<Item = i32>>(values: I) -> String { ... }
```

区别只是不能对 `impl Trait` 参数写 turbofish。返回位置的 `impl Trait`
是"不透明类型"，语义不同，第 14 课展开。

## 二、具体语法

### 13.1 泛型函数

```rust
fn identity<T>(value: T) -> T { value }

fn largest<T: PartialOrd>(values: &[T]) -> Option<&T> { ... }

fn sum<T>(values: &[T]) -> T
where
    T: Copy + std::iter::Sum<T>,
{ ... }
```

- 类型参数写在函数名后的 `<>` 里，可以有多个：`fn f<A, B>(a: A, b: B)`
- 生命周期参数和类型参数可以混写：`fn f<'a, T>(x: &'a T)`
- 返回类型可以继续使用 `T`，调用方按实参推断

### 13.2 约束的写法

```rust
fn f<T: Clone + Ord>(x: T) { ... }        // 内联约束

fn g<T, U>(x: T, y: U) -> String
where
    T: Display,
    U: Display,
{ ... }

fn h<T: ?Sized>(x: &T) { ... }            // 放宽 Sized
```

- 约束是"与"关系；`where` 子句只是排版方式
- 优先用 `where` 写多参数/长约束，签名更可读
- 约束只应该包含函数真正需要的能力，不要"顺手"加一堆

### 13.3 泛型结构体与枚举

```rust
struct Pair<A, B> { first: A, second: B }

enum Either<L, R> {
    Left(L),
    Right(R),
}
```

- 结构体/枚举定义上的泛型参数在其生命周期内都是"未知类型"
- `Option<T>`、`Result<T, E>`、`Vec<T>`、`HashMap<K, V>` 都是标准库的泛型类型
- 不要在类型定义上加不必要的约束；约束放到 `impl` 上更灵活

### 13.4 `impl` 块与特化

```rust
impl<A, B> Pair<A, B> {
    fn new(first: A, second: B) -> Self { ... }
}

impl<A: Display, B: Display> Pair<A, B> {
    fn show(&self) -> String { format!("{} & {}", self.first, self.second) }
}

impl Pair<i32, i32> {
    fn sum(&self) -> i32 { self.first + self.second }
}
```

- `new` 对所有类型可用；`show` 只在可显示时可用；`sum` 只在 `i32` 对时可用
- 特化 impl 是"额外的固有方法"，不是 trait 特化
- 同名方法不能同时出现在泛型 impl 和特化 impl 里

### 13.5 turbofish 与类型标注

```rust
"42".parse::<i32>()                  // 显式指定 T
let values = iter.collect::<Vec<i32>>();
let values: Vec<i32> = iter.collect(); // 等价的标注方式
```

类型推断不出来时（例如 `parse` 的返回类型、`collect` 的目标容器），
用 `::<...>` 或类型标注。错误通常是 E0284 "type annotations needed"。

### 13.6 const 泛型（预览）

```rust
fn first<const N: usize>(values: [i32; N]) -> i32 { values[0] }

let pair = Pair::<i32, i32>::new(1, 2);   // 类型参数也能用 turbofish
```

const 泛型把"长度/大小"也变成编译期参数，第 15 课展开。

### 13.7 `impl Trait` 参数

```rust
fn join_all(values: impl IntoIterator<Item = i32>) -> String { ... }

join_all(vec![1, 2, 3]);
join_all([4, 5]);
```

调用方可以传任何满足约束的类型；函数体内按匿名泛型处理。

## 三、实际应用与最佳实践

### 14.1 通用算法：`largest` / `sum`

```rust
largest(&[3, 9, 2]);            // Some(9)
sum(&[1, 2, 3, 4, 5]);          // 15
```

同一份代码服务 `i32`、`f64`、`&str`（`&str: PartialOrd`）等类型；
单态化后每种类型都是专门优化过的机器码。

### 14.2 泛型容器：`Pair` / `Either`

```rust
let pair = Pair::new(3, 4);
pair.show();                    // "3 & 4"
Pair::new(3, 4).sum();          // 7（只有 Pair<i32, i32> 有）
```

`Either<L, R>` 是"二选一"的泛型联合，常用于错误分支、解析结果、
"成功/降级"两种路径。

### 14.3 泛型缓存：`Cache<K, V>`

```rust
impl<K: Eq + Hash, V> Cache<K, V> {
    fn get_or_insert_with(&mut self, key: K, make: impl FnOnce() -> V) -> &V {
        self.entries.entry(key).or_insert_with(make)
    }
}
```

约束放在 `impl` 上：只有可哈希的键才能使用 `Cache`；`V` 不需要任何约束。
`or_insert_with` 让"未命中才计算"成为惰性语义。

### 14.4 泛型算法：`min_max`

```rust
min_max(&[4, 1, 9, 3, 8]);      // Some((1, 9))
```

`T: Ord + Copy` 覆盖整数、字符、字符串切片等；`Copy` 让循环里可以按值比较。

### 14.5 最佳实践清单

1. **先写具体类型，再抽泛型**：抽象要由重复驱动，不要预先泛化
2. **约束最小化**：只要求真正用到的 trait，调用方负担最小
3. **约束放 `impl`/方法，而不是类型定义**：类型定义保持"无约束"
4. **参数用 `&T`/`&[T]`**，需要拥有或修改再按值/`&mut`
5. **类型推断不出来时用 turbofish**，而不是乱加类型标注
6. **`?Sized` 只给确实要接收 `str`/切片/`dyn` 的函数**
7. **泛型公开 API 是 semver 的一部分**：加约束、改约束都可能破坏下游
8. **类型组合爆炸时评估 `dyn Trait`**：一份代码 vs 多份实例的权衡
9. **用 `cargo bloat` 观察泛型实例的二进制占用**
10. **泛型代码也要写单元测试**：每个具体类型可以各测一遍边界

## 常见陷阱

1. **缺少约束（E0369/E0277）**：在泛型函数里用了 `>`、`+`、`clone` 等能力，
   却没写 `T: PartialOrd`/`T: Clone`；错误在定义处就会报
2. **类型推断失败（E0284）**：`"42".parse().unwrap()` 不知道目标类型；
   写 `parse::<i32>()` 或给变量标注
3. **特化方法调不到（E0599）**：`impl Pair<i32, i32>` 的 `sum` 只对 `i32` 对有效，
   `Pair<&str, &str>` 上不存在
4. **单态化膨胀**：泛型参数组合过多导致二进制变大、编译变慢；
   用 `dyn Trait`、枚举或减少类型参数
5. **`T` 被移动**：按值传入后再用原变量会 E0382；用 `&T` 或 `T: Copy`
6. **`&T` 与 `T` 混用**：`largest` 返回 `&T`，调用方拿到的是引用，需要解引用或复制
7. **`impl Trait` 参数不能 turbofish**：需要显式类型参数时改成普通泛型
8. **给类型定义加多余约束**：`struct S<T: Clone>` 会让所有使用处都被迫满足；
   约束放到需要它的 `impl`
9. **同名方法冲突（E0592）**：泛型 impl 和特化 impl 不能定义同名方法
10. **`?Sized` 忘记加**：想接收 `&str`/`&[T]` 却写了 `T`，编译失败
11. **公开泛型 API 改约束**：下游代码可能直接编译失败；把约束当成 API 契约
12. **`collect` 不知道容器**：`iter.collect()` 需要目标类型，用 turbofish 或标注
13. **约束里缺关联类型**：`T: Iterator` 不够，通常要写 `T: Iterator<Item = u32>`，
    否则 `next()` 的元素类型未知
14. **单态化递归**：泛型函数无限实例化自身会触发编译期递归上限或体积爆炸
15. **误以为泛型是运行时多态**：`Vec<Box<dyn Trait>>` 才是异构集合；
    `Vec<T>` 里 T 是单一具体类型

## 完整示例

见 `12_generics_and_monomorphization.rs`，按 **① 原理验证 → ② 语法演示 → ③ 应用实战**
三段组织，先预测输出再运行（示例输出刻意只用 ASCII，规避 Windows 控制台编码问题）：

```bash
rustc --edition 2024 -D warnings "ABSTRACTION/12_泛型函数与单态化/12_generics_and_monomorphization.rs" -o run.exe
./run.exe
```

示例共 15 行输出，覆盖：同一泛型函数对不同类型生成实例（`type_name` 可见）、
`PartialOrd` 约束、特化 `impl`、`where` 子句、泛型枚举 `Either`、`impl Trait` 参数、
turbofish、泛型 `Cache<K, V>` 与 `min_max`。

## 练习

1. 写 `fn second_largest<T: Ord + Copy>(values: &[T]) -> Option<T>`，
   只遍历一次，处理重复元素与长度不足的情况。
2. 给 `Pair<A, B>` 增加 `map_first`/`map_second`，把 `A`/`B` 映射成新类型，
   并写出对应的泛型签名。
3. 实现泛型 `Stack<T>`：`push`/`pop`/`peek(&self) -> Option<&T>`，
   解释 `peek` 的返回值生命周期为什么绑定到 `&self`。
4. 实现 `Cache<K, V>`，增加 `len`、`contains_key`，并测试命中/未命中时闭包是否被调用。
5. 把 `sum` 改成接收 `impl Iterator<Item = T>` 的版本，比较两种签名的灵活性。
6. 用 `std::any::type_name` 打印 `Vec<i32>`、`Vec<String>`、`Option<&str>` 的类型名，
   解释为什么单态化后它们各不相同。
7. 写一个泛型函数和一个 `dyn Trait` 版本做同样的事，
   从二进制体积、调用开销、异构集合三个方面比较二者。
