# 第 19 课 · 迭代器与惰性求值

> 所需工具链：rustc 1.85+（edition 2024） ｜ 讲解：本文件 ｜ 独立代码：`19_iterators_and_laziness.rs`

## 一、底层原理

### 19.1 Iterator 是"拉取式状态机"

迭代器的全部契约只有一个方法：

```rust
pub trait Iterator {
    type Item;
    fn next(&mut self) -> Option<Self::Item>;
}
```

- 每次 `next()` 从状态机里"拉"出一个元素；返回 `None` 表示结束
- 适配器（`map`/`filter`/`take`...）**不产生元素**，只是把上一个迭代器包起来，
  在 `next()` 里做转换/过滤/截断
- `for x in iter` 展开为：

```rust
let mut iter = IntoIterator::into_iter(iter);
loop {
    match iter.next() {
        Some(item) => { /* body */ }
        None => break,
    }
}
```

- 适配器是零大小或小结构体，经单态化后通常能内联成普通循环；这就是"零成本抽象"
- 只有 `Box<dyn Iterator>` 才有分配 + vtable 间接

`Iterator` 有几个扩展 trait：

| trait | 额外能力 | 典型适配器 |
|---|---|---|
| `DoubleEndedIterator` | `next_back`，可从后往前 | `rev` |
| `ExactSizeIterator` | `len()`，长度精确已知 | `Vec::into_iter` |
| `FusedIterator` | 返回 `None` 后永远返回 `None` | `Chain`/`Map`（大多数） |

注意：普通 `Iterator` **不保证** "None 之后一直是 None"，需要时用 `.fuse()`
或依赖 `FusedIterator`。

### 19.2 惰性求值：适配器只建管道，消费者才驱动

```rust
let mapped = (1..=3).map(|x| {
    println!("visiting {}", x);
    x * 2
});
// 这里一行都不会打印
let values: Vec<i32> = mapped.collect();   // 现在才执行 3 次
```

- **适配器**（adapter）：`map`、`filter`、`take`、`zip`、`chain`、`enumerate`...
  返回新的迭代器，不执行任何元素处理
- **消费者**（consumer）：`collect`、`for`、`sum`、`fold`、`count`、`find`、
  `any`、`all`、`last`、`for_each`... 调用 `next()` 驱动整条链

惰性带来两个重要行为：

1. **短路**：`find`/`any`/`all`/`take` 一旦满足条件就停止，后面的元素不会被处理
2. **无限序列**：`successors`/`repeat`/`from_fn` 可以生成无限迭代器，
   只要用 `take`/`take_while`/`find` 截断就不会死循环

惰性的代价是**错误的出现位置后移**：`map` 里的 `unwrap` 直到消费时才 panic。
需要早失败时用 `try_fold`/`collect::<Result<...>>`，或把校验放到构造阶段。

### 19.3 `IntoIterator` 与三种借用

`for` 和 `collect` 接收的是 `IntoIterator`，不是 `Iterator`：

```rust
for x in &vec { ... }        // &T
for x in &mut vec { ... }    // &mut T
for x in vec { ... }         // T（消费）

vec.iter();                  // Iterator<Item = &T>
vec.iter_mut();              // Iterator<Item = &mut T>
vec.into_iter();             // Iterator<Item = T>
```

| 写法 | 元素类型 | 是否移动容器 |
|---|---|---|
| `&vec` / `vec.iter()` | `&T` | 否 |
| `&mut vec` / `vec.iter_mut()` | `&mut T` | 否 |
| `vec` / `vec.into_iter()` | `T` | 是 |

数组从 Rust 1.53 起实现按值的 `IntoIterator`；edition 2021 起 `array.into_iter()`
也按值解析（更早 edition 会解析成切片迭代器）。

自定义类型也可以实现 `IntoIterator`，让它支持 `for`：

```rust
impl IntoIterator for Numbers {
    type Item = i32;
    type IntoIter = std::vec::IntoIter<i32>;
    fn into_iter(self) -> Self::IntoIter { self.0.into_iter() }
}
```

### 19.4 适配器与消费者分类

适配器（返回新迭代器，惰性）：

| 类别 | 方法 |
|---|---|
| 变换 | `map`、`filter`、`filter_map`、`flat_map`、`flatten`、`scan`、`inspect`、`copied`、`cloned` |
| 截断/跳过 | `take`、`take_while`、`skip`、`skip_while`、`step_by` |
| 组合 | `chain`、`zip`、`enumerate`、`rev`、`peekable` |
| 其他 | `fuse`、`by_ref` |

消费者（驱动迭代器，返回结果）：

| 方法 | 结果 |
|---|---|
| `collect` | 容器/`Result` |
| `fold` / `reduce` | 单值 |
| `sum` / `product` | 数值 |
| `count` / `last` / `nth` | 计数/元素 |
| `find` / `position` | `Option` |
| `any` / `all` | `bool`（短路） |
| `for_each` | `()` |
| `partition` | 两个容器 |
| `try_fold` | `Result`（可提前失败） |

### 19.5 返回值与生命周期

返回迭代器时，要区分"借用"还是"拥有"：

```rust
fn words<'a>(text: &'a str) -> impl Iterator<Item = &'a str> + 'a {
    text.split_whitespace()
}

fn squares(limit: u32) -> impl Iterator<Item = u32> {
    (0..limit).map(|value| value * value)
}
```

- 借用的迭代器生命周期必须绑定到输入（`+ 'a`/`+ '_`）
- 不能返回借用局部变量的迭代器（E0597）
- 需要把迭代器存进结构体/跨 API 传递时，用 `Box<dyn Iterator<Item = ...>>`
  或泛型结构体（第 14、16 课）

### 19.6 性能：零成本从哪里来

- 适配器是普通结构体，`next` 是普通方法；单态化后可内联，最终接近手写循环
- `collect::<Vec<_>>()` 会预分配（依赖 `size_hint`），比"逐个 push"更稳
- 链式调用不会产生中间 `Vec`；中间集合才是额外分配
- `Box<dyn Iterator>` 每层调用一次 vtable 间接
- `count()`/`last()` 必须消费整个迭代器；`len()` 只适用于 `ExactSizeIterator`

## 二、具体语法

### 20.1 实现 `Iterator`

```rust
struct Countdown { current: u32 }

impl Iterator for Countdown {
    type Item = u32;

    fn next(&mut self) -> Option<u32> {
        if self.current == 0 {
            None
        } else {
            let value = self.current;
            self.current -= 1;
            Some(value)
        }
    }
}

let values: Vec<u32> = Countdown { current: 3 }.collect();
```

- 只需实现 `next`；`Iterator` 的其他方法都有默认实现
- `next` 需要 `&mut self`，所以迭代器变量要可变
- 返回 `None` 后是否继续可用取决于是否 `FusedIterator`

### 20.2 实现 `IntoIterator`

```rust
impl IntoIterator for Numbers {
    type Item = i32;
    type IntoIter = std::vec::IntoIter<i32>;

    fn into_iter(self) -> Self::IntoIter {
        self.0.into_iter()
    }
}
```

- `for` 循环用的是 `IntoIterator`
- 可以为 `&Numbers`/`&mut Numbers` 分别实现，返回借用型迭代器

### 20.3 常见适配器

```rust
(1..=5).filter(|v| v % 2 == 1).map(|v| v * v);      // [1, 9, 25]
[1, 2].into_iter().zip(['a', 'b']);                  // [(1,'a'), (2,'b')]
(1..=2).chain(5..=6);                                // 1,2,5,6
"ab cd".split_whitespace().flat_map(|w| w.chars());  // 'a','b','c','d'
(0..).step_by(2).take(3);                            // 0,2,4
```

- `filter_map`：同时过滤和映射（闭包返回 `Option`）
- `scan`：带状态的映射，返回 `Option` 可提前结束
- `inspect`：偷看元素但不改变它（调试用）
- `peekable`：`peek()` 查看下一个元素，不消费

### 20.4 消费者

```rust
(1..=4).fold(0, |acc, v| acc + v);        // 10
(1..=4).sum::<i32>();                      // 10
(1..=10).find(|v| v % 7 == 0);             // Some(7)
(1..=10).any(|v| v == 5);                  // true
"a b a".split_whitespace().count();        // 3
```

- `fold` 是最通用的消费者，`sum`/`count`/`last` 都可以用它表达
- `any`/`all`/`find` 短路
- `nth(n)` 会消费前 n 个；`count`/`last` 会消费全部

### 20.5 `collect` 与 `FromIterator`

```rust
let values: Vec<i32> = (1..=3).collect();
let text: String = ['a', 'b'].into_iter().collect();
let parsed: Result<Vec<i32>, _> = ["1", "x"].iter()
    .map(|s| s.parse::<i32>())
    .collect();
```

- `collect` 依赖目标类型的 `FromIterator`
- `Result` 的 `collect` 遇到第一个 `Err` 就短路
- 类型推断不出来时用 turbofish：`collect::<Vec<_>>()`

### 20.6 `peekable` / `rev` / `zip`

```rust
let mut iter = [1, 2, 3].into_iter().peekable();
let peeked = iter.peek().copied();
let next = iter.next();

let reversed: Vec<i32> = vec![1, 2, 3].into_iter().rev().collect();
```

- `peek()` 需要 `&mut`，返回 `Option<&Item>`
- `rev()` 要求底层实现 `DoubleEndedIterator`
- `zip` 在较短的一侧结束时停止

### 20.7 无限迭代器

```rust
std::iter::successors(Some(1u32), |v| Some(v * 2)).take(5);  // 1,2,4,8,16
std::iter::repeat(0).take(3);                                 // 0,0,0
std::iter::from_fn(|| Some(1)).take(3);                       // 1,1,1
```

- 无限迭代器必须用 `take`/`take_while`/`find` 等截断
- `from_fn` 适合"每次调用计算下一个值"的场景
- `successors` 适合递推序列（斐波那契、幂次）

### 20.8 返回迭代器

```rust
fn squares(limit: u32) -> impl Iterator<Item = u32> {
    (0..limit).map(|value| value * value)
}

fn words<'a>(text: &'a str) -> impl Iterator<Item = &'a str> + 'a {
    text.split_whitespace()
}
```

- 静态分发、无分配；调用方只能按约束使用
- 需要存储/异构时改 `Box<dyn Iterator<Item = T>>`

## 三、实际应用与最佳实践

### 21.1 Fibonacci：无限迭代器 + `take`

```rust
let fib: Vec<u64> = Fibonacci { a: 1, b: 1 }.take(6).collect();
// [1, 1, 2, 3, 5, 8]
```

自定义 `Iterator` 只需维护状态；`take` 负责截断。这种"无限序列 + 消费者"的组合
比预先算好 `Vec` 更灵活。

### 21.2 词频统计：`fold` + `BTreeMap`

```rust
let counts: BTreeMap<&str, usize> = text
    .split_whitespace()
    .fold(BTreeMap::new(), |mut map, word| {
        *map.entry(word).or_insert(0) += 1;
        map
    });
```

`fold` 携带可变累加器；`entry` API 避免重复查找。键借用原文本，零复制。

### 21.3 解析流水线：`map` + `filter` + `sum`

```rust
let even_total: i32 = ["1", "2", "3", "4"]
    .iter()
    .map(|text| text.parse::<i32>().unwrap())
    .filter(|value| value % 2 == 0)
    .sum();
```

中间没有 `Vec`：`map`/`filter` 只是适配器，`sum` 一次驱动。
真实工程里把 `unwrap` 换成 `collect::<Result<...>>` 或 `filter_map`。

### 21.4 最佳实践清单

1. **优先迭代器链**，而不是"先建 `Vec` 再循环"
2. **明确惰性**：适配器不执行，消费者才执行
3. **短路优先**：`find`/`any`/`all` 比 `filter().count()` 高效
4. **避免中间集合**：能链式就链式，减少分配
5. **`iter()` 只读、`iter_mut()` 修改、`into_iter()` 消费**
6. **返回借用迭代器时写清生命周期**
7. **无限迭代器必须截断**
8. **错误用 `collect::<Result<...>>`/`try_fold` 提前失败**
9. **`collect` 目标类型写清楚**（turbofish 或标注）
10. **需要 `rev`/`len` 时确认底层实现了 `DoubleEndedIterator`/`ExactSizeIterator`**

## 常见陷阱

1. **以为 `map` 会立即执行**：适配器惰性，副作用要等消费者
2. **无限迭代器忘记 `take`**：程序挂起；用 `take`/`take_while`/`find`
3. **`rev` 用在非 `DoubleEndedIterator`（E0277）**：如 `from_fn(...).rev()`；
   先 `collect` 或换数据结构
4. **对 `filter` 调 `.len()`（E0599）**：`Filter` 不是 `ExactSizeIterator`；
   用 `count()`
5. **返回借用局部变量的迭代器（E0597）**：改成返回拥有数据的 `Vec`，
   或借用参数
6. **`peekable` 同时 `peek` 和 `next`（E0499）**：`peek()` 的可变借用未结束；
   先 `let peeked = iter.peek().copied();` 再 `next`
7. **`zip` 被较短一侧截断**：长度不等时结果变短，必要时先检查长度
8. **`for x in array` 移动数组**：数组按值迭代；想保留用 `&array`
9. **`iter()` 与 `into_iter()` 混用**：前者借用、后者消费，返回元素类型不同
10. **`take_while` 与 `filter` 混淆**：前者遇到第一个不满足就停止，
    后者继续扫描
11. **`collect::<Result<...>>` 缺类型标注**：推断不出来；写清楚目标容器
12. **`count()` 后还想用迭代器**：消费者会消耗迭代器；需要复用先 `by_ref`
13. **`nth(n)` 以为是 O(1)**：会消费前 n 个元素
14. **`size_hint` 当精确长度**：它只是上下界提示，可能很松
15. **`FusedIterator` 假设**：普通 `Iterator` 可能 `None` 后又返回 `Some`；
    需要时用 `.fuse()`
16. **在 `map` 里做有副作用的 IO**：惰性会让执行时机不可控；用 `for_each` 或显式循环

## 练习

1. 实现 `struct Fibonacci { a: u64, b: u64 }` 的 `Iterator`，取前 10 项求和。
2. 实现 `struct Chunks { data: Vec<i32>, size: usize }` 的 `Iterator`，
   每次返回一个 `Vec<i32>` 块。
3. 用 `Cell` 统计 `map` 实际被调用了多少次，验证惰性与短路。
4. 写一条"解析 CSV → 过滤 → 求和"的迭代器流水线，错误用 `collect::<Result<...>>`。
5. 实现 `fn words<'a>(text: &'a str) -> impl Iterator<Item = &'a str> + 'a`，
   再写一个返回 `Vec<&str>` 的版本，比较分配与生命周期。
6. 用 `fold` + `BTreeMap` 统计词频，并按键排序输出。
7. 用 `any`/`all` 写两个带计数器的短路示例，打印实际检查了多少个元素。
8. 比较 `for` 循环、迭代器链、`Box<dyn Iterator>` 三种写法在可读性和开销上的差异。
