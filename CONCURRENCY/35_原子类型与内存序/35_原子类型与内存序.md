# 第 35 课 · 原子类型与内存序

> 所需工具链：rustc 1.85+（edition 2024） ｜ 讲解：本文件 ｜ 独立代码：`35_atomics_and_ordering.rs`

## 一、底层原理

### 35.1 原子操作解决什么问题

普通 `i32` 的 `+= 1` 在机器层面是"读-改-写"三步，多线程同时执行会丢更新。
原子类型把这个过程交给硬件的一条原子指令（x86 的 `lock xadd`/`cmpxchg`，
ARM 的 `ldrex/strex` 或 LSE 原子指令）：

```rust
use std::sync::atomic::{AtomicUsize, Ordering};

let counter = AtomicUsize::new(0);
counter.fetch_add(1, Ordering::Relaxed);   // 原子地 +1
```

- **原子性**：操作不可分割，不会读到"改了一半"的值
- **内存序**：控制这个原子操作与其他读写之间的**可见性/重排**关系
- 原子类型都实现 `Sync`，可以放进 `Arc` 跨线程共享
- 原子操作只保证**单个原子变量**；多个变量的组合不原子（需要锁）

### 35.2 `Ordering` 的语义

| Ordering | 用于 | 语义 |
|---|---|---|
| `Relaxed` | load/store/RMW | 只保证原子性，不建立同步，不阻止重排 |
| `Acquire` | load/RMW | 后面的读写不能重排到它之前；与 Release 配对 |
| `Release` | store/RMW | 前面的读写不能重排到它之后；向 Acquire 发布 |
| `AcqRel` | RMW | 同时具有 Acquire + Release |
| `SeqCst` | 全部 | 最强，所有 SeqCst 操作有单一全序 |

核心概念：

- **synchronizes-with**：线程 A 用 `Release` 写，线程 B 用 `Acquire` 读到同一个值
  （或更晚的值），则 A 在 Release 之前的写对 B 可见
- **happens-before**：由 synchronizes-with 与程序顺序传递而来
- `Relaxed` **不建立** happens-before；它只保证"这个变量本身"的原子性
- `SeqCst` 在 Acquire/Release 基础上再加全局顺序，最贵但最好推理

常见选择：

- 统计计数：`Relaxed`（不关心顺序，只要不丢更新）
- 发布/消费标志：store `Release`，load `Acquire`
- CAS 循环：成功 `AcqRel`，失败 `Acquire`/`Relaxed`
- 不确定时：`SeqCst`（先正确，再优化）

### 35.3 `compare_exchange` 与 CAS 循环

```rust
let value = AtomicUsize::new(0);
let result = value.compare_exchange(0, 1, Ordering::AcqRel, Ordering::Acquire);
// Ok(0)：成功，旧值是 0
// Err(current)：失败，返回当前值
```

- 成功用 `success` ordering，失败用 `failure` ordering
- **失败 ordering 不能是 `Release`/`AcqRel`**（编译错误）；只能是 `Relaxed`/`Acquire`/`SeqCst`
- `compare_exchange_weak` 允许伪失败（spurious failure），适合循环；`strong` 不会伪失败
- CAS 循环必须重新读取当前值：

```rust
let mut current = value.load(Ordering::Relaxed);
loop {
    match value.compare_exchange_weak(current, current + 1, Ordering::AcqRel, Ordering::Relaxed) {
        Ok(_) => break,
        Err(actual) => current = actual,
    }
}
```

- **ABA 问题**：值从 A 变 B 又变回 A，CAS 会误以为没变；用版本号/标记指针
  （`AtomicUsize` 打包版本 + 指针，或 `crossbeam-epoch`）

### 35.4 原子类型与限制

| 类型 | 说明 |
|---|---|
| `AtomicBool` | 标志位 |
| `AtomicU8`/`U16`/`U32`/`U64`/`Usize` | 无符号整数 |
| `AtomicI8`...`Isize` | 有符号整数 |
| `AtomicPtr<T>` | 裸指针，解引用需要 unsafe |
| `AtomicUsize` | 最常用：计数、索引、版本号 |

限制：

- 没有 `AtomicF32`/`AtomicF64`；用 `to_bits` + `AtomicU32/U64`，或 `Mutex<f64>`
- 整数原子操作会**回绕**（`usize::MAX + 1 == 0`），不会 panic
- `AtomicU64` 在缺少 64 位原子指令的目标上可能不是 lock-free；
  用 `cfg(target_has_atomic = "64")` 做条件编译
- `AtomicPtr` 的解引用、生命周期、内存回收都要 unsafe/额外方案

### 35.5 原子 vs Mutex

| | 原子 | Mutex |
|---|---|---|
| 保护范围 | 单个机器字 | 任意数据/不变量 |
| 阻塞 | 无锁（可能自旋） | 可能阻塞 |
| 组合操作 | 不原子 | 临界区内原子 |
| 复杂度 | 内存序/ABA | 死锁/中毒 |
| 适用 | 计数、标志、简单状态 | 复合结构、业务不变量 |

**不要用多个原子变量维护一个不变量**：读它们时可能看到"中间状态"。
需要一致性就放进同一把锁，或用单个原子打包（版本号/位域）。

### 35.6 自旋锁与 Acquire/Release

```rust
while self.locked.compare_exchange(false, true, Ordering::Acquire, Ordering::Relaxed).is_err() {
    std::hint::spin_loop();
}
// 临界区
self.locked.store(false, Ordering::Release);
```

- `Acquire` 保证临界区内的读写不会跑到加锁之前
- `Release` 保证临界区内的读写对下一个获取者可见
- `spin_loop()` 是给 CPU 的提示（x86 `pause`），减少功耗/流水线惩罚
- 自旋锁适合**极短**临界区；长临界区会烧 CPU，应该用 `Mutex`
- 自旋锁不保证公平，可能饥饿

### 35.7 性能与测试

- 无争用原子操作通常几纳秒；争用同一个 cache line 会"乒乓"，非常贵
- **伪共享（false sharing）**：不同线程写同一 cache line 的不同变量；
  用 padding/`#[repr(align(64))]` 隔离
- `SeqCst` 在 x86 上可能需要 `mfence`/`lock`，比 `Relaxed` 贵；ARM 更明显
- 并发算法用 `loom` 做模型检查；`miri` 不能完全验证弱内存序
- 高争用计数器可以先 per-thread 累加，最后合并

## 二、具体语法

### 36.1 基本操作

```rust
use std::sync::atomic::{AtomicUsize, Ordering};

let value = AtomicUsize::new(0);

value.store(1, Ordering::Relaxed);
let current = value.load(Ordering::Acquire);

let old = value.swap(2, Ordering::AcqRel);
let old = value.fetch_add(3, Ordering::Relaxed);
let old = value.fetch_sub(1, Ordering::Relaxed);
```

- `load`/`store`/`swap`/`fetch_*` 都带 `Ordering`
- `fetch_*` 返回**旧值**
- `swap` 返回旧值并写入新值

### 36.2 标志位

```rust
let stop = AtomicBool::new(false);

stop.store(true, Ordering::Release);
if stop.load(Ordering::Acquire) {
    // 看到 stop 之前的所有写
}
```

- 取消标志/初始化标志用 `Release`/`Acquire`
- 只做统计、不传播其他数据时可以用 `Relaxed`

### 36.3 CAS

```rust
let value = AtomicUsize::new(0);
match value.compare_exchange(0, 1, Ordering::AcqRel, Ordering::Acquire) {
    Ok(old) => println!("swapped from {old}"),
    Err(current) => println!("still {current}"),
}
```

- 成功返回 `Ok(旧值)`，失败返回 `Err(当前值)`
- `compare_exchange_weak` 适合循环，可能伪失败
- 失败 ordering 不能是 `Release`/`AcqRel`

### 36.4 `fetch_update` / `fetch_max` / `fetch_min`

```rust
let value = AtomicUsize::new(5);
let previous = value.fetch_update(Ordering::SeqCst, Ordering::SeqCst, |current| {
    Some(current + 1)
});

let maximum = AtomicUsize::new(3);
maximum.fetch_max(7, Ordering::SeqCst);
```

- `fetch_update` 闭包返回 `None` 表示放弃更新
- 闭包可能被多次调用（CAS 失败重试），不要放副作用
- `fetch_max`/`fetch_min` 返回旧值

### 36.5 自旋锁

```rust
struct SpinLock<T> {
    locked: AtomicBool,
    data: UnsafeCell<T>,
}

unsafe impl<T: Send> Sync for SpinLock<T> {}
```

- `UnsafeCell` 是内部可变性的底层原语
- `unsafe impl Sync` 的证明：锁保证互斥，Acquire/Release 保证可见性
- guard `Drop` 时 `store(false, Release)`

### 36.6 目标能力检查

```rust
#[cfg(target_has_atomic = "64")]
fn use_u64() { /* AtomicU64 可用 */ }
```

- 嵌入式/32 位目标注意原子宽度
- 不满足时可以降级到 `Mutex` 或软件模拟

## 三、实际应用与最佳实践

### 37.1 多维指标

```rust
struct Stats {
    requests: AtomicUsize,
    errors: AtomicUsize,
}
```

- 每个指标独立原子，适合监控计数
- 但 `requests` 与 `errors` 之间**没有一致性保证**；需要快照一致就加锁
- 高争用用 per-thread 计数 + 定期汇总

### 37.2 自旋锁

- 只保护极短临界区（几条指令）
- 临界区内不做 IO/分配/阻塞
- 争用高时退化严重；生产用 `Mutex`/`parking_lot`
- 自旋锁不解决优先级反转/公平性

### 37.3 最佳实践清单

1. **不确定就用 `SeqCst`**，先正确再优化
2. **计数用 `Relaxed`**，发布/消费用 `Acquire`/`Release`
3. **CAS 循环用 `compare_exchange_weak`** 并处理伪失败
4. **失败 ordering 不用 `Release`/`AcqRel`**
5. **多个变量的一致性用锁**，不要用多个原子拼
6. **注意 ABA**，需要版本号/epoch
7. **`AtomicPtr` 必须有内存回收方案**
8. **避免伪共享**，热变量按 cache line 隔离
9. **自旋锁只用于极短临界区**
10. **并发算法用 `loom` 验证**

## 常见陷阱

1. **用 `Relaxed` 做发布/消费**：其他数据可能不可见；改 Acquire/Release
2. **`compare_exchange` 失败 ordering 写 `Release`**：编译错误
3. **CAS 循环不更新 `current`**：永远失败/死循环
4. **ABA 问题**：值回到原值，CAS 误判
5. **多个原子变量当整体**：读到不一致的组合
6. **原子整数溢出**：回绕不 panic；业务上要检查
7. **没有 `AtomicF64`**：用 bits 或 `Mutex`
8. **`AtomicPtr` 直接解引用**：悬垂指针/生命周期问题
9. **32 位目标上的 64 位原子**：可能非 lock-free
10. **自旋锁临界区太长**：CPU 空转、吞吐下降
11. **自旋锁不公平**：线程饥饿
12. **`SeqCst`  everywhere**：正确但性能差
13. **伪共享**：两个热计数器在同一 cache line
14. **`fetch_update` 闭包有副作用**：可能执行多次
15. **`compare_exchange_weak` 不写循环**：伪失败导致逻辑丢失
16. **`AtomicBool` 当互斥锁保护多行代码**：没有临界区语义
17. **忘记 `Ordering` 参数**：Rust 强制显式，别随便选
18. **在原子变量上做非原子读改写**：`load` 后 `store` 不是原子复合
19. **用原子实现引用计数**：直接用 `Arc`，别手写
20. **没有并发测试**：只跑单线程无法发现内存序问题
