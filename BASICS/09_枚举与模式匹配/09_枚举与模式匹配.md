# 第 09 课 · 枚举与模式匹配

> 所需工具链：rustc 1.85+（edition 2024） ｜ 讲解：本文件 ｜ 独立代码：`09_enums_and_matching.rs`

## 一、底层原理

### 9.1 枚举是"带标签的联合体"（sum type）

C 的 `union` 让多个字段共享同一块内存，但不知道当前哪个字段有效；Rust 的枚举补上了
**标签（discriminant）**，并且由编译器保证"只能按当前变体访问"：

```rust
enum Shape {
    Point,                                  // 单元变体
    Circle(f64),                            // 元组变体
    Rect { width: f64, height: f64 },       // 结构体变体
}
```

在内存里，枚举 = **标签 + 所有变体中最大的负载**（再加对齐所需的填充）：

| 部分 | `Shape` 的大小 |
|---|---|
| 最大负载 | `Rect` 的 2 × `f64` = 16 字节 |
| 标签/填充 | 8 字节 |
| 合计 | **24 字节**（示例输出 `shape_size=24`） |

这带来一个反直觉但重要的结论：**`Shape::Point` 也占 24 字节**。枚举的大小由最大的
变体决定，而不是由当前变体决定。

递归枚举必须通过 `Box`/`Rc` 引入间接层，否则类型大小会无限展开：

```rust
enum List { Cons(i32, List), Nil }        // E0072: recursive type has infinite size
enum List { Cons(i32, Box<List>), Nil }   // OK：Box 是指针，大小固定
```

与 trait 对象相比，枚举是**封闭**的：所有变体在定义处列完，`match` 可以穷尽检查；
trait 对象是**开放**的：任何类型都可以实现 trait，调用走 vtable（第 16 课）。

| 维度 | 枚举 | trait 对象 |
|---|---|---|
| 扩展方式 | 修改枚举定义（可能破坏现有 `match`） | 新增 `impl` 即可 |
| 分发方式 | 静态跳转/查表 | vtable 动态分发 |
| 值大小 | 最大变体的大小 | 固定两个指针（胖指针） |
| 穷尽检查 | 有 | 无 |
| 适用场景 | 封闭状态集、协议消息、AST | 开放插件、多实现 |

### 9.2 判别值与 niche 优化

无数据的枚举可以显式指定判别值，并直接 `as` 成整数：

```rust
enum Level { Low = 1, Mid = 5, High = 10 }
Level::High as u8      // 10
size_of::<Level>()     // 1：判别值放得下 u8
```

带数据的枚举**不能** `as`（E0605），要用 `match` 取负载。

更有意思的是 **niche 优化**：如果某个类型存在"无效位模式"，`Option<T>` 可以直接
用这个无效值表示 `None`，不额外占字节：

| 类型 | 大小 | 机制 |
|---|---|---|
| `Option<&T>` | 同 `&T` | 空指针作为 `None` |
| `Option<Box<T>>` | 同 `Box<T>`（8） | 空指针作为 `None` |
| `Option<NonZeroU32>` | 4 | `0` 是无效值，用 0 表示 `None` |
| `Option<bool>` | 1 | `bool` 只有 0/1，2 表示 `None` |
| `Option<u8>` | 2 | `u8` 没有无效值，必须加独立标签 |

所以 Rust 的"可空指针"不是语言层面的空引用，而是 `Option<&T>` 这个零成本枚举；
`None` 在机器层面就是空指针。

### 9.3 `match` 的编译期检查与降级

`match` 先做**穷尽性检查**，再做**可达性检查**：

- 漏掉变体/范围 → E0004：`non-exhaustive patterns: E::B not covered`
- 前面的臂已经覆盖、后面的臂永远匹配不到 → `unreachable_patterns` 警告
- **守卫不算穷尽**：`n if n > 0 => ...` 不能证明覆盖所有 `i32`，后面必须补 `_`

```rust
match value {
    0 => "zero",
    n @ 1..=5 => "small",
    n if n < 0 => "negative",
    _ => "other",            // 必须有
}
```

降级后，编译器读判别值，生成 `SwitchInt`（整数/枚举标签）或跳转表；
守卫会变成额外的条件分支。整个过程**没有 vtable、没有堆分配**。

对公开 API 的枚举加 `#[non_exhaustive]`，下游 `match` 必须写 `_`，
这样以后新增变体不会破坏下游代码。

### 9.4 模式匹配的本质：解构 + 绑定

模式不是"if 的语法糖"，它同时做三件事：

1. **测试**：当前值是否匹配这个形状
2. **解构**：把复合值拆成字段
3. **绑定**：把字段绑定到新名字

模式分两类：

| 类别 | 含义 | 允许出现的位置 |
|---|---|---|
| 不可反驳（irrefutable） | 任何值都匹配，如 `let (a, b) = pair` | `let`、函数参数、`for` |
| 可反驳（refutable） | 可能不匹配，如 `Some(x)`、`0..=5` | `match`、`if let`、`while let`、`let-else` |

因此 `let Some(x) = opt;` 是**编译错误**（E0005），必须用 `if let` 或 `let-else`。

**绑定模式（match ergonomics）**：当被匹配的值是引用时，模式会自动按引用绑定：

```rust
let message = Message::Move { x: 3, y: 4 };
match &message {
    Message::Move { x, y } => ...   // x: &i32, y: &i32
    ...
}
```

老代码里的 `ref`/`ref mut` 就是手动做这件事；现代 Rust 通常不需要写。

**or-pattern**（`|`）要求所有分支绑定**同名同类型**的变量，否则 E0408：
`Some(x) | None` 不合法，因为 `None` 分支没有 `x`。

**`@` 绑定**同时"测试 + 命名"：

```rust
n @ 1..=5 => format!("small({n})")
```

### 9.5 枚举与所有权

- `match` 一个**按值**传入的枚举会移动它；只想读就匹配 `&value`
- 匹配 `&mut value` 时绑定是 `&mut T`，可以就地修改
- 从枚举里"取出"非 `Copy` 负载会移动；取出后原枚举部分失效
- `Option::take`/`replace` 是把负载从 `&mut` 中安全取出的常用工具（第 05 课）

## 二、具体语法

### 10.1 定义与实例化

```rust
enum IpAddr {
    V4(u8, u8, u8, u8),
    V6(String),
}

let home = IpAddr::V4(127, 0, 0, 1);
let loopback = IpAddr::V6(String::from("::1"));
```

- 变体可以是单元、元组或结构体形式
- 变体名与枚举名同处一个命名空间，用 `IpAddr::V4` 访问
- 无数据变体可以指定判别值：`enum Level { Low = 1, Mid = 5 }`
- `#[repr(u8)]` / `#[repr(C)]` 用于 FFI 时固定表示

### 10.2 `match` 的完整形式

```rust
match value {
    0 => "zero",
    n @ 1..=5 => "small",
    n if n < 0 => "negative",
    n if n % 2 == 0 => "even",
    _ => "other",
}
```

- 每个臂是 `模式 [if 守卫] => 表达式`
- 臂按顺序尝试，第一个匹配的生效；后面的不可达会被警告
- `|` 组合多个模式：`'a' | 'e' | 'i' | 'o' | 'u'`
- 范围模式：`1..=5`、`'a'..='z'`
- `@` 绑定：`n @ 1..=5`
- `_` 通配，`..` 忽略结构体剩余字段
- `match` 是表达式，所有臂的类型必须一致

### 10.3 `if let` / `while let` / `let-else` / `matches!`

```rust
if let Some(value) = option { ... } else { ... }

while let Some(top) = stack.pop() { ... }

let Some(value) = option else { return; };     // else 必须发散

if matches!(command, Command::Quit) { ... }     // 只关心是否匹配
```

- `if let`/`while let` 只处理一个模式；多个模式用 `match`
- `let-else` 的 `else` 块必须 `return`/`break`/`continue`/`panic!`（发散）
- `matches!` 返回 `bool`，不提供负载

### 10.4 解构结构体、元组、切片

```rust
let Point { x, y } = point;                 // 结构体
let (a, b) = (1, 2);                        // 元组
let [first, rest @ ..] = array;             // 数组/切片模式
let Message::Move { x, y } = message else { return; };
```

- 结构体模式可以用 `..` 忽略未列出的字段
- 切片模式按长度匹配：`[]`、`[_]`、`[first, .., last]`
- 绑定 `rest @ ..` 把剩余部分绑定成子切片

### 10.5 绑定模式与引用

```rust
match &message {
    Message::Write(text) => text.len(),      // text: &String
    Message::Move { x, y } => ...            // x: &i32
}

match &mut counter {
    Counter { count } => *count += 1,        // count: &mut i32
}
```

- 匹配 `&T` 时，绑定默认是引用；匹配 `&mut T` 时，绑定是 `&mut`
- 需要按值取出时，匹配所有权值本身（会移动）
- `ref`/`ref mut` 是旧写法，现代 Rust 由 match ergonomics 自动处理

### 10.6 枚举的方法

```rust
impl Shape {
    fn area(&self) -> f64 {
        match self {
            Shape::Point => 0.0,
            Shape::Circle(radius) => PI * radius * radius,
            Shape::Rect { width, height } => width * height,
        }
    }
}
```

`match self` 是枚举方法的标准写法：`&self` 让所有变体都以引用匹配，
不移动枚举本身。

### 10.7 `#[non_exhaustive]`

```rust
#[non_exhaustive]
pub enum Error {
    Io(String),
    Parse(String),
}
```

定义该枚举的 crate 内部仍可穷尽匹配；其他 crate 必须写 `_` 兜底。
它让"以后新增变体"成为非破坏性变更。

## 三、实际应用与最佳实践

### 11.1 表达式树：递归枚举 + `Box`

```rust
enum Expr {
    Num(i64),
    Add(Box<Expr>, Box<Expr>),
    Mul(Box<Expr>, Box<Expr>),
}

fn eval(expr: &Expr) -> i64 {
    match expr {
        Expr::Num(value) => *value,
        Expr::Add(left, right) => eval(left) + eval(right),
        Expr::Mul(left, right) => eval(left) * eval(right),
    }
}
```

递归枚举是 AST、JSON、配置树、查询计划的自然表达。`Box` 提供间接层，
`&Expr` 让求值只借用、不消耗树。

### 11.2 状态机：`match self` 决定迁移

```rust
impl State {
    fn next(self) -> State {
        match self {
            State::Idle => State::Running(0),
            State::Running(n) if n < 2 => State::Running(n + 1),
            State::Running(_) => State::Done,
            State::Done => State::Done,
        }
    }
}
```

枚举把"状态集合"变成类型，编译器保证所有迁移都被处理；
`self` 接收者让迁移天然是"消费旧状态、产生新状态"。

### 11.3 命令解析：枚举建模 + `?`

```rust
enum Command {
    Quit,
    Echo(String),
    Move { x: i32, y: i32 },
}
```

解析函数用 `split_whitespace` + `?` + `parse().ok()?`，失败返回 `None`。
调用方用 `filter_map` 跳过非法行，得到 `Vec<Command>`。

### 11.4 最佳实践清单

1. **用枚举表达"有限状态/互斥变体"**，不要用一堆 `bool` + `Option` 拼
2. **让 `match` 保持穷尽**，不要习惯性写 `_` 掩盖新变体
3. **守卫不参与穷尽性**：有守卫的臂后面记得补 `_`
4. **优先匹配 `&value`**，只读时不要移动值
5. **`let-else` 处理早退**，把正常路径留在主线
6. **递归类型用 `Box`/`Rc`**，并注意递归深度（可能栈溢出）
7. **公开枚举加 `#[non_exhaustive]`**，为未来扩展留余地
8. **用 `Option`/`Result` 表达缺失与失败**，不要用哨兵值（`-1`、空串）
9. **`matches!` 只用于布尔判断**，需要负载就 `match`/`if let`
10. **`match` 的臂保持短小**，复杂逻辑抽成函数，保持"模式表"可读

## 常见陷阱

1. **漏掉变体（E0004）**：新增变体后所有 `match` 都要更新；
   这正是枚举"封闭"的价值，不要用 `_` 把它掩盖掉
2. **在 `let` 里用可反驳模式（E0005）**：`let Some(x) = opt;` 不合法；
   用 `if let`、`let-else` 或 `match`
3. **守卫臂导致不穷尽（E0004）**：`n if n > 0 => ...` 不算覆盖，
   必须补 `_` 或完整范围
4. **or-pattern 绑定不一致（E0408）**：`Some(x) | None` 中 `None` 没有 `x`；
   所有分支必须绑定同名同类型变量
5. **递归枚举没加 `Box`（E0072）**：类型大小无限；用 `Box<Self>` 打断递归
6. **带数据的枚举 `as` 整数（E0605）**：只有无数据枚举能 `as`；
   带数据要 `match` 取负载
7. **直接 `match` 一个 `String`**：`match s { "a" => ... }` 类型不匹配；
   先 `s.as_str()`
8. **匹配 `&T` 后误以为拿到了所有权**：绑定是引用，需要 `*` 或 `clone`；
   想移动就匹配值本身
9. **`_` 与 `_x` 混淆**：`_` 不绑定（值当场丢弃），`_x` 绑定到作用域结束；
   锁守卫、资源句柄上差异很大（第 01 课）
10. **整数 `match` 忘记兜底**：`match n { 1 => ..., 2 => ... }` 对 `i32`
    不穷尽；要么写全范围，要么加 `_`
11. **`unreachable_patterns`**：前面的臂已经覆盖，后面的模式永远不生效；
    调整顺序或删除
12. **`#[non_exhaustive]` 后忘记 `_`**：跨 crate 匹配会编译失败；
    这正是它的目的，加兜底即可
13. **递归求值栈溢出**：深 AST 用显式栈/迭代，而不是无限递归
14. **`match` 臂类型不一致**：所有臂必须返回同一类型；需要不同类型时返回枚举
15. **在守卫里做副作用**：守卫应只读、无副作用；复杂逻辑放到臂体里

## 练习

1. 定义 `enum IpAddr { V4(u8, u8, u8, u8), V6(String) }`，
   实现 `fn to_string(&self) -> String`，并解释为什么这里不用 `as`。
2. 给 `Expr` 增加 `Sub`/`Div` 变体，`eval` 返回 `Option<i64>`：
   除零返回 `None`，其余正常求值。
3. 实现红绿灯状态机 `enum Light { Red, Green, Yellow }`，
   `fn next(self) -> Light`，并列出每个状态的持续时间。
4. 用 `let-else` 和 `?` 写一个解析 `"key=value"` 的函数，
   失败时返回 `None`，并用 `filter_map` 批量解析。
5. 用切片模式写 `fn classify_slice(values: &[i32]) -> &'static str`，
   区分空、单元素、首尾相同、其他。
6. 复现 E0072（递归枚举没有 Box），记录错误信息，并用 `Box` 修复。
7. 实现 `fn describe(n: i32) -> &'static str`，同时使用范围、守卫和 `_`，
   并测试 `i32::MIN`、`-1`、`0`、`5`、`6`、`i32::MAX` 六个边界。
8. 把一段 `if let ... else if let ... else` 改写成 `match`，
   比较两者的穷尽性和可读性。
