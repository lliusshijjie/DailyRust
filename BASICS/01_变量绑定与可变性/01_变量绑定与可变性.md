# 第 01 课 · 变量绑定、可变性与遮蔽

> 所需工具链：rustc 1.85+（edition 2024） ｜ 讲解：本文件 ｜ 独立代码：`01_bindings_and_mutability.rs`

## 一、底层原理

### 1.1 `let` 不是"声明变量"，是"把模式绑定到值"

在 C/C++/Java 里，声明语句先给变量分配一块内存，再往里写值；变量就是那块内存。
Rust 的 `let` 换了个模型：**先求值右边的表达式，再按左边的模式把结果拆开、绑定名字**。

```rust
let (a, b) = (1, 2);              // 解构元组
let [first, .., last] = [1, 2, 3];  // 解构数组
let Some(x) = opt else { return };  // 解构 Option
```

名字只是编译期的"访问路径"：编译器通过 MIR 和借用检查决定每个值放在哪里
（栈、寄存器还是堆），`let` 本身不承诺任何内存布局。由此可以推出本课的所有行为：

| `let` 写法 | 语义 | 运行时痕迹 |
|---|---|---|
| `let x = 5;` | 模式 `x` 绑定值 5 | 通常被优化进寄存器 |
| `let x: i32 = 5;` | 同上，额外标注类型 | 无 |
| `let x;` | 延迟初始化，读取前必须所有路径已赋值 | 无 |
| `let (a, b) = t;` | 把 `t` 拆成两个绑定 | 无 |
| `let _ = expr;` | 模式 `_` 不绑定，值在语句结束即丢弃 | 有 Drop 调用 |
| `let _x = expr;` | 绑定了名字，值活到作用域结束 | 有 Drop 调用（延后） |

### 1.2 `mut` 是"绑定的权限位"，不是类型的一部分

```rust
let mut x: i32 = 5;
```

这里 `x` 的类型仍然只是 `i32`。`mut` 是写在**模式**上的一个许可，告诉借用检查器
"这个绑定允许被赋值、允许被 `&mut` 借用"。对比其他语言：

| 语言 | 可变性写在哪 | 后果 |
|---|---|---|
| C++ | `const` 是**类型的一部分**（`const int&`） | 参与重载决议，可 `const_cast` 绕过 |
| Java | `final` 修饰变量/字段 | 编译期检查，反射仍可改 |
| Rust | `mut` 是**绑定的权限** | 不影响类型、泛型与 ABI，无法安全绕开 |

所以 `let x: i32` 和 `let mut x: i32` 会生成相同的机器码：借用检查结束后，
`mut` 不再影响代码生成，LLVM IR 里看不到它的痕迹。也正因如此，
`fn take(x: i32)` 这种签名对两种绑定一视同仁——Rust 没有"常量性进入类型"
那种机制（`&T` 与 `&mut T` 才是在类型层面表达独占/共享）。

> 注意：`mut` 只管"这个绑定能不能被直接赋值/可变借用"。含内部可变性的类型
> （`Cell`、`RefCell`、`Mutex`）即使绑定不可变，也能修改自己的内容——这是第 41 课的主题。

### 1.3 遮蔽（shadowing）是"新建一个同名绑定"，不是赋值

```rust
let s = "42";        // &str
let s: i32 = s.parse().unwrap();  // 新绑定，类型变成 i32
```

两条关键结论：

1. **旧值不会被提前销毁**。旧绑定仍然活到它所在作用域的末尾，只是名字被新绑定
   遮住、无法再访问。因此析构顺序是"新绑定先 drop，旧绑定后 drop"。
2. **遮蔽是编译期重命名，零运行时成本**；它和"重新赋值"完全不是一回事。

| 操作 | 是否创建新绑定 | 能否换类型 | 旧值何时 drop |
|---|---|---|---|
| `x = 5;` | 否（要求 `x` 是 `mut`） | 否 | 不涉及 |
| `let x = 5;`（同名） | 是 | 能 | 作用域结束（早于新绑定） |
| `let x = x;` | 是 | 同名同型也算 | 对非 `Copy` 类型是**移动**，不是拷贝 |

### 1.4 `const` 与 `static`：编译期内联 vs 全局单例

| | `const` | `static` |
|---|---|---|
| 求值时机 | 编译期（const eval） | 编译期初始化，运行期只读 |
| 实例数量 | 无独立实例，每个使用点**内联** | 全程序**一个**实例 |
| 地址 | 不保证稳定（取引用得到临时值，可能被常量提升） | 固定地址，`&'static` |
| 可变性 | 永远不可变（不能写 `const mut`） | 不可变；`static mut` 需 `unsafe` |
| 典型用途 | 数组长度、const 泛型实参、魔法数命名 | 全局配置、计数器、单例 |
| 类型要求 | 类型必须写全，值必须可在编译期算出来 | 类型必须写全，且通常要求 `Sync` |

`static mut` 在 **edition 2024** 里对它的引用是**硬错误**（`static_mut_refs`），
因为共享的可变全局天然不健全。可变全局的正确姿势是 `AtomicUsize`、
`OnceLock`、`Mutex`——用类型系统把同步责任表达出来。

### 1.5 明确初始化分析：未初始化读取是编译错误，不是 UB

Rust 没有"默认值"这回事：`i32` 不会自动是 0，`String` 不会自动是空串。
编译器用数据流分析证明**读取前必已初始化**，否则报错 `E0381`。
这消除了 C/C++ 里最常见的一类未定义行为，也让"先声明、分支里再赋值"这种
写法是安全的：

```rust
let decided: i32;
if cond { decided = 1 } else { decided = -1 }
println!("{}", decided);   // 编译器已证明两条路径都赋过值
```

## 二、具体语法

### 2.1 基本形式

```rust
let name = expr;                    // 类型由初始化表达式推断
let name: Type = expr;              // 显式标注
let mut name = expr;                // 可变绑定
let name;                           // 延迟初始化（之后所有路径都要赋值）
let (a, b) = expr;                  // 模式解构
let (a, b): (i32, i32) = expr;      // 标注写在模式之后，而不是名字之后
let Some(x) = opt else { ... };     // let-else，失败分支必须发散（1.65+）
let _ = expr;                       // 立即丢弃
let _name = expr;                   // 绑定但抑制 unused 警告
```

规则细则：

- `mut` 只能出现在**模式里的绑定位置**：`let mut x`、`let (mut a, b)`、
  `if let Some(mut v) = ...`；`let x: mut i32` 是非法的
- `mut` 不是类型的一部分，也不能出现在函数签名的类型里：
  `fn f(x: mut i32)` 非法；要表达"函数内可改"写 `fn f(mut x: i32)`
- `&mut T` 与 `mut` 是两件事：`&mut T` 是**对 pointee 的可变借用**，
  `let mut r: &T` 是**引用本身可重新指向**
- 不可变绑定不能被赋值（`E0384`），也不能被 `&mut` 借用
- `const`/`static` 必须显式写类型，名字用 `SCREAMING_SNAKE_CASE`
- `const` 可以写在函数体内；`static` 也可以，但生命周期仍是 `'static`

### 2.2 遮蔽的作用域

```rust
let s = "42";
let s: i32 = s.parse().unwrap();   // 遮蔽：类型从 &str 变成 i32
{
    let s = s * 2;                 // 只在这个块内遮蔽
    println!("{s}");               // 84
}
println!("{s}");                   // 42（外层的新绑定）
```

- 同一作用域内可以反复遮蔽
- 内层块的遮蔽在块结束时失效，外层绑定重新可见
- 旧绑定不会因为"被遮住"而提前 drop，它仍参与作用域结束时的逆序析构

### 2.3 `_` 与 `_name` 不是一回事

```rust
let _ = make_guard();       // 模式 _ 不绑定：值在语句结束就 drop
let _guard = make_guard();  // 绑定了名字：值活到作用域结束
```

- `_` 表示"我不关心这个值"，它不会绑定名字，因此值在**语句结束**立即析构
- `_name` 是正常绑定，只是名字以下划线开头，编译器不再报 `unused_variables`
- 两者在锁、文件、临时缓冲区的生命周期上会导致完全不同的行为（见常见陷阱 1）

### 2.4 `const` / `static` 的写法

```rust
const MAX_POINTS: u32 = 100_000;   // 编译期常量
const N: usize = 3;
let zeros = [0u8; N];              // const 可作数组长度

static BANNER: &str = "rust-daily";              // 全局只读
static HITS: AtomicUsize = AtomicUsize::new(0);  // 全局可变：原子量
static CONFIG: OnceLock<String> = OnceLock::new(); // 只初始化一次的全局配置
```

- `static` 初始化表达式必须是编译期可求值的；初始化后不会再被"赋值"
- `static` 不会在程序退出时执行 `Drop`（没有全局析构阶段）
- 共享的 `static` 要求类型实现 `Sync`；`Cell` 这类类型不能直接做 `static`
- `static mut` 能用，但要 `unsafe`，且 edition 2024 起禁止对它取引用——
  新代码直接用 `Atomic*` / `OnceLock` / `Mutex`

## 三、实际应用与最佳实践

### 3.1 场景：用遮蔽写"解析流水线"

```rust
let input = "  42, 7 ,9 ";
let input = input.trim();
let input = input.replace(' ', "");
let nums: Vec<i32> = input.split(',').map(|s| s.parse().unwrap()).collect();
// [42, 7, 9]
```

每一步都产生一个新绑定，全程没有 `mut`，也不需要给中间结果起
`trimmed_input`、`cleaned_input` 这种名字。读者从上到下看到的是"值的形态变化"，
这正是遮蔽最合适的场景——**值的转换，而不是状态的修改**。

### 3.2 场景：全局配置与全局计数

```rust
static CONFIG: OnceLock<String> = OnceLock::new();
let config = CONFIG.get_or_init(|| String::from("release"));

static HITS: AtomicUsize = AtomicUsize::new(0);
HITS.fetch_add(1, Ordering::Relaxed);
```

`OnceLock` 把"只初始化一次"从约定变成了类型保证；原子量让计数无需锁也无需
`unsafe`。真正复杂的共享状态再上 `Mutex`（第 33 课）。

### 3.3 默认不可变：让编译器告诉你哪里需要 `mut`

先写 `let`，编译失败（`cannot assign twice to immutable variable`）时再加 `mut`。
反过来做（先到处 `mut`）会失去"这段值不会变"的阅读保证，还会触发 `unused_mut` 警告。
`mut` 的范围越小，能同时存在的 `&mut` 冲突就越少——这是 Rust 借用检查友好的写法。

### 3.4 命名规范（编译器不强制，但生态一致）

| 对象 | 风格 | 例子 |
|---|---|---|
| 绑定、函数、模块、字段 | `snake_case` | `max_points`、`read_config` |
| 类型、trait、枚举变体 | `UpperCamelCase` | `ParseError`、`Some` |
| `const` / `static` | `SCREAMING_SNAKE_CASE` | `MAX_POINTS` |
| 故意不用的绑定 | 前缀 `_` | `_guard`、`_unused` |

### 3.5 最佳实践清单

1. **默认 `let`，按需 `mut`**：让"不会变"成为默认阅读预期
2. **用遮蔽做值转换**，用 `mut` 做真正的状态演进——两者语义不同，不要混用
3. **纯常量用 `const`**，需要固定地址/全局单例才用 `static`
4. **可变全局用 `Atomic*` / `OnceLock` / `Mutex`**，不要写 `static mut`
5. **`let _ = ...` 只用于确实要立刻丢弃的值**；要持有资源就起名字
6. **所有权能移动就不 `clone()`**：`let x = x;` 对非 `Copy` 类型是零成本移动
7. **让 lint 说话**：`-D warnings` 下 `unused_mut`、`unused_variables` 都是错误，
   它们正好提示"可变性声明过度"或"值没被用上"

## 常见陷阱

1. **`let _ = lock.lock().unwrap();` 会立即释放锁**。`_` 不绑定名字，
   `MutexGuard` 在语句结束就 drop，临界区变成空的。要持有守卫必须写
   `let _guard = lock.lock().unwrap();`
2. **遮蔽不等于提前释放**。旧绑定活到作用域结束，Drop 顺序是"新绑定先、旧绑定后"，
   和"重新赋值"的直觉不同。
3. **`let x = x;` 对非 `Copy` 类型是移动**。搬的是所有权，不是数据；
   如果之后还想用"原来那个"，得先 `clone()`——但多数时候不如直接让旧绑定退休。
4. **`unused_mut`**：声明了 `mut` 却从未修改，`-D warnings` 下直接编译失败。
   这是好事：它说明可变性声明过度了。
5. **`static mut` 在 edition 2024 取引用是硬错误**，而且它本来就是
   `unsafe` 的地雷区；改用原子量或 `OnceLock` 能从根上避免数据竞争。
6. **`const` 没有地址稳定性**。`&MAX_POINTS` 得到的是临时值（可能被常量提升），
   不要依赖"两次取地址相同"；需要地址就用 `static`。
7. **延迟初始化必须覆盖所有分支**。漏掉一条路径就是 `E0381` 编译错误——
   好消息是这永远轮不到运行时 UB。
8. **循环里的 `let` 每次迭代都是新绑定**，跨迭代不会保留值；
   要在迭代间累计状态，变量必须声明在循环外。

## 练习

1. 用遮蔽把 `" 3,4 ,5 "` 解析成 `Vec<i32>`，要求全程不出现 `mut`，
   并且不产生第二级变量名（只有 `input` / `nums`）。
2. 写一个带 `Drop` 的类型，分别用 `let _ =` 和 `let _x =` 创建，验证两段输出出现的位置；
   再把其中一个放进内层块，观察析构顺序。
3. 用 `const` 定义数组长度与循环上界，用 `static` + `OnceLock` 定义只初始化一次的配置，
   并解释为什么这里不用 `static mut`。
4. 用 `let ... else` 重写一个"解析失败就提前返回"的函数，与 `match` 版本比较
   嵌套深度和可读性。
