# 第 02 课 · 表达式与控制流

> 所需工具链：rustc 1.85+（edition 2024） ｜ 讲解：本文件 ｜ 独立代码：`02_expressions_and_control_flow.rs`

## 一、底层原理

### 2.1 Rust 是表达式语言：语句只是"丢掉值"的表达式

C/C++ 里 `if`、`for`、`while` 都是**语句**，语句不能出现在需要值的位置；
Rust 把绝大多数结构都做成**表达式**——块、`if`、`match`、`loop` 都产生值。
语法层面只有三类东西：

| 类别 | 例子 | 产生值吗 |
|---|---|---|
| 条目 item | `fn f() {}`、`struct S;` | 不产生（定义） |
| 语句 statement | `let x = 1;`、`f();` | 表达式语句会求值但丢弃结果 |
| 表达式 expression | `1 + 2`、`if c { a } else { b }`、`{ ... }` | 产生类型化的值 |

一个块 `{ ... }` 的结构是"若干语句 + 可选的尾表达式"；**尾表达式决定块的值**，
没有尾表达式（或尾表达式带了分号）时块的值是单元类型 `()`：

| 形式 | 类型 | 说明 |
|---|---|---|
| `{ 1 + 2 }` | `i32` | 尾表达式即块值 |
| `{ 1 + 2; }` | `()` | 分号把值变成"被丢弃的表达式语句" |
| `{ let y = 5; y * 2 }` | `i32` | `let` 语句之后才是尾表达式 |
| `if c { 1 } else { 2 }` | `i32` | 两个分支同型 |
| `loop { break 7; }` | `i32` | `break` 携带值 |
| `a = 1` | `()` | 赋值本身是表达式，值恒为 `()` |
| `return 7` | `!` | 发散：永不正常返回 |

这也解释了 C 的一个经典 bug 为什么在 Rust 里不存在：`if x = 1 { }` 里
赋值表达式类型是 `()`，不是 `bool`，编译器直接拒绝。

### 2.2 `if` 是表达式，不是"带分支的语句"

```rust
if cond { A } else if other { B } else { C }
```

- `cond` 必须是 `bool`，Rust **没有真值判断**（`if 1 {}` 编译错误）
- 用作**值**时：必须有 `else`，且所有分支类型必须一致（没有隐式数值转换）
- 用作**语句**时：`else` 可省，分支的值被丢弃
- 花括号不能省；`if (x > 0)` 的额外括号会触发 `unused_parens` 警告
- `else if` 只是 `else { if ... }` 的语法糖，链式写法在语法树里是右嵌套的

编译器把 `if` 降成一个双出口分支 + 汇合块：MIR 里是 `SwitchInt` +
两个 `Goto`，汇合处用临时局部变量承接各分支的值（SSA 化后就是 phi 节点）。
所以"`if` 是表达式"是**语法层**的设计，运行期和手写语句分支没有任何差别，
既不会多一次函数调用，也不会分配闭包。

### 2.3 `loop` / `while` / `for` 的类型差异是有原因的

| 循环 | 至少执行一次？ | 表达式类型 | 能否 `break value` |
|---|---|---|---|
| `loop { ... }` | 是 | `break` 的值类型 | 能 |
| `while cond { ... }` | 否（条件可能一开始就假） | `()` | 不能 |
| `for x in it { ... }` | 否（迭代器可能为空） | `()` | 不能 |

`while` 和 `for` 可能一次都不执行，语言无法保证"一定有一个值"，所以它们的类型
只能是 `()`；而 `loop` 保证至少进入循环体一次，正常退出**只能**通过 `break`，
于是 `break value` 可以定义整个循环表达式的值。没有 `break` 的 `loop {}`
永远不返回，类型是 `!`。

两种循环都可以理解为 `loop` 的语法糖（这也是标准库/语言参考里的降级方式）：

```rust
// while 大致等价于
loop {
    if !cond { break; }
    body
}

// for 大致等价于
let mut iter = IntoIterator::into_iter(expr);
loop {
    match iter.next() {
        Some(pat) => { body }
        None => break,
    }
}
```

`for` 自己不暴露 `break value`，是因为它把 `loop` 包了一层、退出路径由
`match` 的 `None` 分支统一接管；要带值退出，就自己写 `loop` + `match`。

### 2.4 发散类型 `!`：让分支"类型不同"也能统一

`return`、`break`、`continue`、`panic!`、`unreachable!`、`todo!`、
永不 `break` 的 `loop {}`、`std::process::exit` 的类型都是 `!`。
`!` 是"没有值"的类型，可以被强制转换成任意类型，因此：

```rust
let x: i32 = if cond { 1 } else { return };   // return 是 !，整条 if 仍是 i32
let y: u8 = match flag { true => 7, false => panic!("no") };
```

这条规则的实际价值是：**错误/退出路径不必扭曲正常路径的类型**。
但要小心 `!` 只是"类型上永远不返回"，`panic!` 仍然会真的 panic；
`unreachable!()` 也不是编译期证明，只是运行期断言。

### 2.5 MIR 与 LLVM：控制流不产生额外抽象成本

- MIR 用基本块 + 终止指令（`SwitchInt` / `Goto` / `Return` / `Unreachable` / `Call` / `Drop`）表示控制流
- `if` → `SwitchInt` 双分支，汇合后把分支值写进同一个临时变量
- `while` / `for` → 回边（back edge），`break` / `continue` → 跳转
- LLVM 里就是 `br` + `phi`；分支简单且无副作用时还会优化成 `select`

对照第 36 课的 async：真正的"控制流状态机"成本来自跨 `.await` 的挂起恢复；
普通 `if`/`loop` 不保存任何跨调用状态，所以表达式导向不会带来运行时开销。

## 二、具体语法

### 2.1 块与分号规则

```rust
let a = { 1 + 2 };              // 3
let b = { 1 + 2; };             // () —— 分号把尾表达式变成语句
let c = { let x = 5; x * 2 };   // 10

fn f() -> i32 { 5 }             // OK：尾表达式就是返回值
fn g() -> i32 { 5; }            // 编译错误：返回类型是 ()
```

规则细则：

- 块的值 = 最后一个**不带分号**的表达式；没有尾表达式时是 `()`
- 表达式语句会丢弃值，因此"有返回值的表达式"单独成句时必须加分号：
  `f();`；块状表达式（`if`/`match`/`loop`/`while`/`for`/块）作语句可省分号，
  但此时它的类型必须是 `()`——`if true { 1 } else { 2 }` 不加分号会报类型错误
- `let` 语句的值也是 `()`，不能出现在需要值的位置（没有 C 的逗号表达式）
- `return` 之后的代码不会被求值，但会触发 `unreachable_code` 警告

### 2.2 if 的具体写法

```rust
if cond { ... }                       // 语句用法：else 可省
if cond { ... } else { ... }          // 值用法：类型必须一致
if cond { 1 } else if other { 2 } else { 3 }
```

- 条件必须能求值为 `bool`；`if Some(1) {}`、`if 0 {}` 都不合法
- 值用法下所有分支同型；`if c { 1 } else { 2u8 }` 不会自动转换，直接报错
- 没有三元运算符：`let x = if c { a } else { b };` 就是它
- `if` 分支里的块可以有语句、可以早退（`return`），不影响整条 `if` 的类型

### 2.3 循环与标签

```rust
loop { ... }                                  // 无限循环（靠 break 退出）
let v = loop { ... break 42; };               // break 带值
while cond { ... }
while let Some(x) = iter.next() { ... }
for item in collection { ... }
for i in 0..n { ... }                         // 0..n 不含 n，0..=n 含 n
```

- `break` / `continue` 默认作用于**最近一层**循环；标签可以指定外层：
  `'outer: for ... { break 'outer; }`、`continue 'outer;`
- 标签也能标在块上（1.65+），把块当作"可提前退出的表达式"：
  `let v = 'blk: { if c { break 'blk 1; } 2 };`
- `break 'label value` 合法；`continue` 只能带标签、不能带值
- `while` / `for` 不能 `break value`（它们的类型是 `()`）
- `while true { ... }` 会触发 `while_true` 警告——要无限循环就写 `loop`
- `for` 接收任何 `IntoIterator`：`&v` 迭代出 `&T`，`v.iter().enumerate()` 带下标，
  `(1..=3).rev()` 反向；数组在 edition 2021 起按值迭代

### 2.4 早退、`let-else` 与 `?`

```rust
fn half(x: i32) -> Option<i32> {
    if x % 2 != 0 {
        return None;              // 早退：前置条件不满足就结束
    }
    Some(x / 2)
}

fn parse(s: &str) -> i32 {
    let Ok(v) = s.parse::<i32>() else {
        return -1;                // else 块必须发散（return/break/panic/continue）
    };
    v
}
```

- `return` 是表达式（类型 `!`），可以出现在任何表达式位置
- `let-else` 把"不匹配就退出"压成两行，避免 `match` 的多层缩进（1.65+）
- `?` 是 Result/Option 的专用控制流糖，展开规则见第 23 课

### 2.5 模式作为条件：`if let` / `while let`

```rust
if let Some(v) = opt { ... } else { ... }
while let Some(v) = stack.pop() { ... }
```

这是"控制流 + 模式匹配"的接口，`if let` 当作值时 `else` 分支类型也要一致。
匹配的穷尽性、守卫、绑定方式等细节留到第 09 课。

## 三、实际应用与最佳实践

### 3.1 用 `break` 值替代"外部 mut 结果变量"

```rust
fn find_first_prime(threshold: u32) -> u32 {
    let mut candidate = threshold + 1;
    loop {
        if is_prime(candidate) { break candidate; }
        candidate += 1;
    }
}
```

对比"先 `let mut result = 0;`、循环里满足条件就赋值、最后再返回"的写法：
`break value` 让"循环的产出"直接成为函数返回值，少一个生命周期横跨整个函数的
可变变量，也少一处"忘记初始化"的可能。

### 3.2 重试循环：`continue` 表示"这轮不算"，`break` 带出终态

```rust
let mut attempts = 0;
let outcome = loop {
    attempts += 1;
    if attempts < 3 { continue; }
    break "ok after 3 attempts";
};
```

这就是"有限状态机"的最朴素形态：进入循环 → 判断 → 继续或退出。
真实工程里把 `continue` 换成"重建连接"、把 `break` 换成返回结果即可。

### 3.3 嵌套搜索用标签，不要用布尔标志

```rust
'rows: for row in 0..3 {
    for col in 0..3 {
        if row == 1 && col == 2 {
            found = Some((row, col));
            break 'rows;      // 一次跳出两层
        }
    }
}
```

用 `found_flag` 逐层检查的写法既多一个变量，又容易漏掉某一层。
标签把"跳到哪一层"直接写在 `break` 上，读代码时不需要推理。

### 3.4 用块表达式收敛临时作用域

```rust
let parsed = {
    let raw = "  42 ";
    raw.trim().parse::<i32>().unwrap()
};
```

`raw` 只活在这个块里，不会污染外层命名空间；`parsed` 直接拿到最终值。
这是"临时变量 + 立即计算"最干净的写法，比先声明 `let raw` 再 `let parsed` 更局部。

### 3.5 最佳实践清单

1. **优先表达式绑定**：`let x = if ... { } else { }`，而不是先 `let mut x;` 再赋值
2. **三种循环各司其职**：`for` 遍历、`while` 条件成立期间、`loop` 靠 `break` 退出
3. **用 `break` 值承载结果**，不要用外部可变变量收集循环产出
4. **嵌套退出用标签**，不要用布尔标志逐层检查
5. **分支保持同型**；需要表达"不同类型的结果"时用枚举（第 09 课）
6. **早退优先**：`return` / `let-else` 把异常路径放前面，主逻辑不缩进
7. **尾表达式别多写分号**：`{ 5 }` 是 `i32`，`{ 5; }` 是 `()`
8. **条件里只放 `bool`**：复杂条件抽成命名函数，读起来就是一句自然语言
9. **不要写 `while true`**：无限循环用 `loop`，让"没有正常出口"一眼可见
10. **`!` 只用于真正的不可达/终止路径**，不要用它掩盖逻辑错误

## 常见陷阱

1. **尾表达式多写一个分号**：`fn f() -> i32 { 5; }` 返回 `()`，编译失败。
   这是新手最常见的错误，报错信息通常是 `mismatched types: expected i32, found ()`
2. **`if` 当值用却漏了 `else`**：`let x = if c { 1 };` 直接报错，
   因为条件为假时没有值可用
3. **分支类型不一致**：`if c { 1 } else { 2u8 }` 不会自动转换；
   数值字面量默认是 `i32`，需要显式统一
4. **`while` / `for` 里写 `break value`**：编译错误，只有 `loop` 能带值
5. **`if` 条件不是 `bool`**：`if 1 {}`、`if Some(1) {}` 都不行，没有真值判断
6. **`break` 只跳出最近一层**：三层嵌套里想一次退出，必须给外层循环加标签
7. **多个 `break` 的值类型必须一致**：`loop` 里两处 `break` 一个 `i32`
   一个 `&str`，整条表达式就无法定型
8. **`loop {}` 永远不返回**：类型是 `!`，`let x: i32 = loop {};` 能编译，
   但程序会卡死——编译器帮不了你，这属于逻辑错误
9. **赋值表达式是 `()`**：`a = b = 1` 编译错误；`if x = 1 {}` 同样错误
10. **块状表达式省略分号的前提是类型为 `()`**：`if true { 1 } else { 2 }`
    单独成句会报类型错误，加了分号（丢弃值）才能作为语句
11. **`unreachable_code` 警告**：`return` / `panic!` 之后的语句不会被求值，
    但仍需通过类型检查
12. **`continue` 不会跳过迭代器推进**：`for` 的下一轮仍会自动 `next()`，
    手动写 `while let` 时则要自己保证不会漏掉推进
