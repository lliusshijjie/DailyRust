# 第 04 课 · 复合类型：元组、数组、切片

> 所需工具链：rustc 1.85+（edition 2024） ｜ 讲解：本文件 ｜ 独立代码：`04_tuples_arrays_slices.rs`

## 一、底层原理

### 4.1 三种类型，三种"存放方式"

| 类型 | 元素类型 | 长度 | 内存位置 | 本质 |
|---|---|---|---|---|
| 元组 `(A, B, C)` | 可以不同 | 类型里固定 | 内联在值里 | 产品类型（product type） |
| 数组 `[T; N]` | 必须相同 | 编译期常量 `N` | 内联在值里 | 定长连续存储 |
| 切片 `[T]` | 必须相同 | 运行期 `len` | 借用别人的内存 | 未定长类型（DST）的视图 |
| `Vec<T>`（对照） | 必须相同 | 运行期 `len`/`cap` | 堆上 | 拥有所有权的动态数组 |

- 元组和数组都是**内联值**：`[u8; 1024]` 就是 1024 个字节直接长在变量里，
  没有额外指针、没有长度头；`size_of::<[u8; 1024]>() == 1024`
- 切片**不是值**，而是"指向一段连续内存的借用视图"：`&[T]` 是
  数据指针 + 长度两个机器字（胖指针）
- 三者都可以零拷贝互相转换：`&[T; N]` / `&Vec<T>` → `&[T]`，
  `&[T]` → `&[u8]`（按字节视图，需 `bytemuck` 之类的 unsafe 库）

### 4.2 元组：没有字段名的产品类型

```rust
let point = (3, 5);      // 类型 (i32, i32)
let (x, y) = point;      // 解构
point.0                   // 字段访问
```

- 字段按位置访问，**不能用变量索引**（`t[i]` 是编译错误 E0608）；
  元素类型不同，本来就无法统一成"第 i 个元素的类型"
- `()` 是零大小单元类型；单元素元组必须写 `(1,)`，`(1)` 只是带括号的 `1`
- 标准库为元组实现常用 trait 的上限是 **12 个元素**（`Debug`、`Clone`、
  `PartialEq` 等），超过 12 个请改用结构体
- 元组字段的布局在 `repr(Rust)` 下**不保证声明顺序**（编译器可以重排以减少 padding），
  所以不能拿元组做 FFI 或按字节序列化；FFI 用 `#[repr(C)]` 结构体（第 47 课）
- 元素按**声明顺序**析构；而函数内的局部变量之间按**声明逆序**析构

元组解决的是"临时组合几个不同类型的值"：多返回值、`zip`/`enumerate` 的元素、
`HashMap` 的 entry。字段一多、语义一复杂，就该升级成命名结构体（第 08 课）。

### 4.3 数组：长度进入类型，所以零成本

```rust
let a: [u8; 4] = [1, 2, 3, 4];
let b = [0u8; 4];          // 重复初始化
```

- `N` 是类型的一部分：`[i32; 3]` 与 `[i32; 4]` 是**不同类型**，
  编译器为每个 `N` 单态化（第 12 课），因此数组没有运行期长度字段
- `size_of::<[T; N]>() == N * size_of::<T>()`；长度是编译期常量，
  常量索引的越界检查可以在编译期完成，运行期索引则做一次 `i < N` 比较
- 数组在栈上（或作为结构体字段内联），**大数组要小心栈溢出**：
  `[u8; 16 * 1024 * 1024]` 直接当局部变量通常会把栈撑爆，改用 `Vec<u8>` 或 `Box<[u8]>`
- 初始化要求元素可复制：`[expr; N]` 会复制 `expr` 共 N 份，
  因此 `T: Copy`（或 `expr` 是 const）；非 Copy 元素用
  `std::array::from_fn(|i| ...)` 逐个构造
- edition 2021 起数组**按值**实现 `IntoIterator`：`for x in arr` 拿到的是元素本身
  （之前版本会解析成 `&T`，这是 2018 代码迁移时常见的差异）
- 数组元素按索引顺序析构：`[Tag("a"), Tag("b")]` 先 drop a 再 drop b

### 4.4 切片：DST + 胖指针

`[T]` 是**未定长类型**（dynamically sized type, DST）：编译器不知道它有多大，
所以它不能作为局部变量、不能按值返回，只能待在指针后面：

```rust
&[T]        // 共享切片：(&ptr, len)
&mut [T]    // 可变切片：(&mut ptr, len)
Box<[T]>    // 拥有所有权的切片：同样是胖指针
```

- `size_of::<&[u8]>() == 2 * size_of::<&[u8; 4]>()`：前者是胖指针（2 个字），
  后者是普通指针（1 个字）
- `&[T; N]` 到 `&[T]` 是 **unsized coercion**（自动加长度），不需要手动转换；
  数组本身没有 `Deref` 到切片，`arr.len()` 是方法解析时自动借用成切片的
- 区间索引 `&arr[1..3]` 不是复制，而是把指针 +1、长度设为 2 的新视图，O(1)
- `split_at`、`chunks`、`windows`、`iter` 全部基于同一段内存，零分配
- `Vec<T>` 通过 `Deref<Target = [T]>` 获得切片方法，`&vec` 也会自动退化为 `&[T]`

**边界检查**：`arr[i]` 在运行期比较 `i < len`，越界**panic**（release 也一样，
这与整数溢出检查不同）；`get(i)` 则返回 `Option<&T>`。优化器在能证明下标安全时
（例如 `for x in &arr` 的迭代）会消除检查。

切片最大的价值是**统一接口**：数组、`Vec`、`Box<[T]>`、内存映射缓冲区、
网络报文片段，全部可以用 `&[T]` 表达，函数只写一份。

### 4.5 所有权与 Copy 的边界

- 元组/数组的每个元素都 `Copy` 时，整体才 `Copy`；否则赋值是**移动**
- 不能从数组/元组里"按索引 move 出"一个非 Copy 元素（E0508）：
  `let s = array[0];` 会在原位置留下一个"洞"
  → 用 `into_iter()` 消耗数组、`std::mem::take(&mut array[0])`、或 `Option::take`
- 数组整体移动是允许的（`let b = array;`），因为洞被整体接管了
- 切片只是借用，**不拥有**数据；返回切片必须能证明它借用的数据活得更久（第 07 课）

## 二、具体语法

### 2.1 元组

```rust
let pair = (1, "one");            // (i32, &str)
let unit: () = ();                // 零大小
let single = (42,);               // 单元素元组，注意逗号
let (number, name) = pair;        // 解构
let nested = (1, (2, 3));
let (a, (b, c)) = nested;         // 嵌套解构
```

- 字段用 `.0`、`.1`：`pair.0`
- 交换两个变量：`let (a, b) = (b, a);`
- 函数返回元组：`fn min_max(v: &[i32]) -> (i32, i32)`
- 元组作为 `match` 分支的模式（第 09 课）
- 元组不能实现 `Index`，所以没有 `t[0]`；要遍历异构元组只能手动解构

### 2.2 数组

```rust
let a = [1, 2, 3];                // [i32; 3]，类型推断
let b: [u8; 4] = [0; 4];          // 重复初始化
let c = [[0u8; 3]; 3];            // 3x3 二维数组
let empty: [u8; 0] = [];          // 零长数组，size 为 0

a.len();                          // 3（元素个数）
a[0];                             // 10（越界会 panic）
a.get(10);                        // None（安全索引）
&a[1..3];                         // 子切片视图
```

规则细则：

- 长度必须是编译期常量：`let n = 5; let a = [0; n];` 不合法（除非 `n` 是 `const`）
- 常量泛型函数：`fn first<const N: usize>(a: [i32; N]) -> i32 { a[0] }`
- `[expr; N]` 要求 `expr: Copy`（或常量表达式）
- 按值迭代、按引用迭代、按可变引用迭代，分别得到 `T`、`&T`、`&mut T`
- 数组没有 `push`/`pop`；需要动态长度就换 `Vec`

### 2.3 切片与索引

```rust
let a = [1, 2, 3, 4, 5];
let s: &[i32] = &a;               // 数组 -> 切片（自动加长度）
let mid = &a[1..4];               // [2, 3, 4]
let head = &a[..2];               // [1, 2]
let tail = &a[2..];               // [3, 4, 5]
let all = &a[..];                 // 整个数组

let (left, right) = a.split_at(2);        // ([1,2], [3,4,5])
a.chunks(2);                              // [[1,2], [3,4], [5]]
a.windows(2);                             // [[1,2], [2,3], [3,4], [4,5]]
a.first();                                // Option<&i32>
a.get(2);                                 // Option<&i32>
a.contains(&3);                           // true（要求 PartialEq）
```

规则细则：

- 区间是左闭右开：`0..n` 不含 `n`，`..=n` 含 `n`
- `&a[range]` 越界会 panic；用 `a.get(range)` 得到 `Option<&[T]>`
- 切片索引要求 `SliceIndex`：整数、`Range`、`RangeTo`、`RangeFrom`、
  `RangeInclusive`、`RangeToInclusive`、`RangeFull` 都可以
- `chunks(0)`、`windows(0)` 会 panic（窗口/块大小必须 > 0）
- `split_at(i)` 在 `i > len` 时 panic；`split_at_checked`（1.80+）返回 `Option`
- 切片上的 `sort`/`binary_search`/`iter` 等都要求 `&mut`/`&` 借用

### 2.4 切片模式

```rust
match slice {
    [] => "empty",
    [_] => "single",
    [_, _] => "pair",
    [first, .., last] => "many",          // first/last 是 &T
    _ => unreachable!(),
}

if let [head, tail @ ..] = slice {         // tail 是 &[T]
    // ...
}
```

- 切片模式天然按长度分支，编译器检查穷尽性
- `..` 匹配"任意多个元素"；`rest @ ..` 把剩余部分绑定成子切片
- 匹配 `&[T]` 时，绑定默认是引用（match ergonomics，第 09 课细讲）
- 长度已知时更推荐直接 `let [a, b] = arr;`（数组模式要求长度完全匹配）

### 2.5 数组、切片、Vec 之间的转换

| 从 | 到 | 写法 |
|---|---|---|
| `[T; N]` | `&[T]` | `&arr` 或 `&arr[..]`（unsized coercion） |
| `Vec<T>` | `&[T]` | `&vec` 或 `vec.as_slice()` |
| `Vec<T>` | `Box<[T]>` | `vec.into_boxed_slice()` |
| `&[T]` | `[T; N]` | `slice.try_into()`（长度不符返回 `Err`） |
| `&[T]` | `Vec<T>` | `slice.to_vec()`（分配 + 复制） |
| `[T; N]` | `Vec<T>` | `Vec::from(arr)` 或 `arr.to_vec()` |

## 三、实际应用与最佳实践

### 3.1 函数参数用 `&[T]`，不要用 `&Vec<T>`

```rust
fn stats(values: &[i32]) -> (i32, i32, i32) { ... }

stats(&[4, 1, 9, 3, 8]);      // 数组
stats(&vec_data);             // Vec 自动退化
stats(&vec_data[1..]);        // 子切片
```

`&Vec<T>` 只能接收 Vec，还多了一层间接；`&[T]` 能接收所有连续序列的视图，
是 Rust API 的标准写法（需要动态增长时才用 `&mut Vec<T>`）。

### 3.2 多返回值用元组，字段一多就换结构体

```rust
let (min, max, sum) = stats(&values);
```

两三个值用元组很自然；到四个以上、或需要文档说明每个字段时，
命名结构体（第 08 课）可读性和可维护性都更好。

### 3.3 固定小缓冲用数组，动态数据用 Vec

- 协议头、校验和、固定大小的 key：`[u8; 32]`
- 配置里的固定表：`[(u8, &str); 4]`
- 长度运行期才知道：`Vec<T>`
- 超大固定缓冲：`Box<[u8; N]>` 或 `Vec<u8>`，避免栈溢出

### 3.4 切片模式做协议/参数解析

```rust
fn parse_frame(frame: &[u8]) -> Option<&[u8]> {
    match frame {
        [0xCA, 0xFE, payload @ ..] => Some(payload),
        _ => None,
    }
}
```

比手写 `if frame.len() >= 2 && frame[0] == 0xCA ...` 更贴近协议文档，
也不用担心下标越界。

### 3.5 排序、二分与窗口统计

```rust
let mut data = [5, 3, 1, 4, 2];
data.sort();                                  // 要求 T: Ord
data.binary_search(&3);                       // 要求已排序
let sums: Vec<i32> = [1, 2, 3, 4].windows(2)
    .map(|w| w[0] + w[1])
    .collect();
```

`binary_search` 在未排序的切片上结果没有意义（不是报错，是静默错误），
这是最容易踩的"逻辑坑"之一。

### 3.6 最佳实践清单

1. **参数用 `&[T]` / `&mut [T]`**，只在需要增删元素时用 `&mut Vec<T>`
2. **索引不可信输入用 `get`**，把越界变成 `Option` 而不是 panic
3. **小固定集合用数组**，运行期长度用 `Vec`；大数组别放栈上
4. **元组不超过 2–3 个字段**，再多用命名结构体
5. **用切片模式替代手写长度判断**，让穷尽性检查帮忙
6. **转换用 `try_into` 而不是 `as`**，长度不符时能拿到 `Err`
7. **排序用 `sort`/`sort_by`，二分前确认有序**
8. **返回切片要绑定生命周期**（第 07 课），不要让借用悬空
9. **FFI/序列化不要依赖元组或数组的字段顺序**，用 `#[repr(C)]` 和显式编码
10. **理解 Copy 边界**：非 Copy 数组不能按索引移动，用 `into_iter` 消耗它

## 常见陷阱

1. **`[String::new(); 3]` 编译失败**：重复初始化要求 `Copy`（E0277）。
   改用 `std::array::from_fn(|_| String::new())`，或先建 `Vec` 再 `try_into`
2. **按索引移动非 Copy 元素**：`let s = array[0];` 报 E0508
   "cannot move out of type `[String; 1]`"。用 `array.into_iter().next()`、
   `mem::take` 或 `clone`
3. **元组不能用变量索引**：`t[i]` 报 E0608；异构元素没有统一的元素类型，
   要遍历就解构或用结构体
4. **`(1)` 不是元组**：单元素元组必须写 `(1,)`，否则只是加了括号的表达式
5. **越界索引 panic**：`arr[arr.len()]` 在 debug 和 release 都 panic；
   用 `get` 或迭代器避免
6. **区间写成 `..=len`**：`&arr[0..=arr.len()]` 越界；含上界的场景要想清楚
7. **`len()` 不是字节数**：`[u32; 4].len()` 是 4，`size_of` 才是 16
8. **`&Vec<T>` 参数**：限制了调用方，还不必要地多一层指针；改用 `&[T]`
9. **大数组爆栈**：几百 KB 以上的数组别放局部变量；用 `Vec`/`Box`
10. **数组和 Vec 不能直接赋值**：`let v: Vec<i32> = arr;` 类型不匹配；
    用 `arr.to_vec()` 或 `Vec::from(arr)`
11. **切片借用的生命周期**：`fn f() -> &[i32] { &[1,2,3] }` 不能编译，
    返回的切片必须来自参数（第 07 课）
12. **`binary_search` 用在未排序数据上**：不报错，但结果错误
13. **`chunks(0)`/`windows(0)` panic**：窗口大小必须大于 0
14. **`for x in arr` 会移动非 Copy 数组**：之后不能再用 `arr`；
    想保留就写 `for x in &arr`

## 练习

1. 写 `fn second_largest(values: &[i32]) -> Option<i32>`，要求只遍历一次、
   不使用排序；长度为 0 或 1 时返回 `None`。
2. 用切片模式解析帧：`[0xCA, 0xFE, payload @ ..]` 返回 payload，
   其他输入返回 `None`；再用 `[_, len, body @ ..] if body.len() == *len as usize`
   写一个带长度校验的版本。
3. 用 `try_into` 把 `&[i32]` 转成 `[i32; 4]`，并分别测试长度 3、4、5 的输入，
   观察 `Err` 的行为。
4. 用 `windows(3)` 求"连续三个数的最大和"，并说明为什么 `windows` 比
   手写下标更不容易越界。
5. 把 `[[u8; 4]; 4]` 的二维数组分别按行、按列求和，比较
   `iter().flatten()` 与双重 `for` 的写法。
6. 解释 `[String::new(); 3]` 为什么编译失败，给出两种修法并比较适用场景。
