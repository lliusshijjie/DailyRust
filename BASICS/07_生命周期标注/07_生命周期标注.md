# 第 07 课 · 生命周期标注

> 所需工具链：rustc 1.85+（edition 2024） ｜ 讲解：本文件 ｜ 独立代码：`07_lifetimes.rs`

## 一、底层原理

### 7.1 生命周期是编译期的"区域"，不是运行期值

每个引用都有一个**生命周期**：它指向的数据至少在多长的一段程序范围内有效。
`'a` 这种写法是给这个"区域"起名字，方便在签名里表达引用之间的关系。

关键事实：

- 生命周期是**编译期概念**，在生成机器码之前就被完全擦除；
  `size_of::<&i32>() == size_of::<&'static i32>()`，引用永远只是一个指针
- 生命周期**不等于词法作用域**：NLL 之后，一个借用的区域是"从创建到最后一次使用"
  的那组程序点，而不是整个 `{}` 块
- 借用检查器会为每个引用推断具体的区域；我们写的 `'a` 只是给这些区域起的名字

### 7.2 为什么函数需要标注：借用契约必须写在签名里

函数体是单独检查的，调用方看不到函数体。签名就是双方之间的**契约**：
"返回值能活多久"必须能从参数推出来。

```rust
fn longest(x: &str, y: &str) -> &str   // 编译错误 E0106
```

编译器无法判断返回的引用来自 `x` 还是 `y`，因此不知道该给它多长的生命周期。
加上标注后就清楚了：

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str
```

它的含义是：**只要两个输入都至少活到 `'a`，输出就至少活到 `'a`**。
调用时 `'a` 取两个实参借用区域的**交集**（较短的那个），所以返回值一定不会悬垂。

标注不是"延长"或"缩短"生命周期，只是把"输出依赖输入"这件事写进类型系统。

### 7.3 省略规则（lifetime elision）

为了少写噪音，Rust 在**函数/方法签名**上有一套省略规则：

| 规则 | 内容 |
|---|---|
| 1 | 每个被省略的**输入**生命周期各获得一个独立的参数 |
| 2 | 如果恰好只有**一个**输入生命周期，它被赋给所有被省略的**输出**生命周期 |
| 3 | 如果有 `&self` 或 `&mut self`，它的生命周期被赋给所有被省略的输出 |

因此：

```rust
fn first_word(text: &str) -> &str          // 规则 2：输出 = text 的借用
fn announce(&self) -> &str                 // 规则 3：输出 = &self 的借用
fn longest(x: &str, y: &str) -> &str       // 两个输入，规则失效 -> E0106
```

省略规则**不适用于**结构体/枚举字段：字段里存引用必须显式写生命周期参数。

### 7.4 `'static` 的两种含义

这是最容易混淆的概念，必须区分：

| 写法 | 含义 | 例子 |
|---|---|---|
| `&'static T` | 引用本身在**整个程序**期间有效 | 字符串字面量、`static` 项、`Box::leak` |
| `T: 'static` | **T 不包含**比 `'static` 更短的借用 | `String`、`Vec<u8>`、`i32` 都满足 |

也就是说：

- `String` 是 `'static` 的（它拥有数据，不借任何东西），但它**不是** `&'static str`
- `&'a str` 只有在 `'a: 'static` 时才是 `'static`
- `fn keep<T: 'static>(v: T)` 既能接收 `String`，也能接收 `&'static str`；
  传 `&local` 会报 E0597（`local` 活不够长）

两个常见推论：

- `Box<dyn Trait>` 默认是 `Box<dyn Trait + 'static>`；要装短生命周期的借用，
  必须写 `Box<dyn Trait + 'a>`
- `std::thread::spawn` 要求闭包 `'static`（不能借用栈上的局部变量）；
  需要借用局部变量时用 scoped threads（第 31 课）

### 7.5 结构体里的生命周期

结构体如果存引用，就必须声明生命周期参数：

```rust
struct Excerpt<'a> {
    part: &'a str,        // 实例不能活得比 part 指向的数据更久
}

impl<'a> Excerpt<'a> {
    fn announce(&self) -> &str { self.part }
}
```

- 结构体的生命周期由字段里的引用决定：`Excerpt<'a>` 的实例不能超出 `'a`
- `impl` 块也要写 `impl<'a> Excerpt<'a>`；较新的写法可以写 `impl Excerpt<'_>`
- 多个字段可以有多个生命周期：`struct Pair<'a, 'b> { first: &'a str, second: &'b str }`
- 自引用结构体（字段指向自己的另一个字段）无法安全构造，需要 `Pin`（第 37 课）

### 7.6 生命周期约束与型变（variance）

**约束**用 `:` 表达"活得更久"：

```rust
fn pick<'a, 'b: 'a>(x: &'a str, y: &'b str) -> &'a str   // 'b 至少和 'a 一样长
fn f<T: 'a>(value: T)                                      // T 活得比 'a 长
```

**型变**描述"生命周期/类型参数能否被替换成子类型"：

| 类型 | 对生命周期 `'a` | 对类型 `T` | 直觉 |
|---|---|---|---|
| `&'a T` | 协变（可缩短） | 协变 | 只读，短的可以当长的用 |
| `&'a mut T` | 协变 | **不变** | 可写，不能把短命值写进长命槽 |
| `Box<T>` | — | 协变 | 独占但只读视角 |
| `Cell<T>` / `RefCell<T>` | — | **不变** | 内部可变性，写入会破坏假设 |
| `fn(T) -> U` | — | 逆变 / 协变 | 参数位置方向相反 |

型变是很多"为什么这个生命周期不能缩短"报错的根源。日常写业务代码很少需要显式
推理它，但看到"lifetime may not live long enough"且代码看起来合理时，值得回来查表。

### 7.7 高阶生命周期（HRTB）

有些 API 需要表达"对**任意**生命周期都成立"，用 `for<'a>`：

```rust
fn apply<F>(f: F) -> String
where
    F: for<'a> Fn(&'a str) -> &'a str,
{
    let owned = String::from("hello");
    f(&owned).to_string()
}
```

`for<'a> Fn(&'a str) -> &'a str` 读作"对任意 `'a`，都能接收 `&'a str` 并返回
`&'a str`"。闭包和迭代器适配器里经常隐式用到它；普通业务代码通常不需要手写。

### 7.8 临时值的生命周期扩展

在**特定语法形式**下，绑定到局部变量的临时值会被延长到该变量的作用域：

```rust
let x = &String::from("temp");     // 临时 String 被延长到 x 的作用域
println!("{}", x);
```

但这不是普遍规律：

```rust
fn make() -> String { String::from("temp") }
let r = make().as_str();           // E0716：临时值在语句结束就释放
```

需要跨语句借用时，先把临时值绑定到一个变量，再借它：

```rust
let owned = make();
let r = owned.as_str();
```

## 二、具体语法

### 8.1 函数签名

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str   // 显式：输出绑定到两个输入
fn first_word(text: &str) -> &str                    // 省略：单输入
fn echo(text: &str) -> &'_ str                       // '_ 占位符，等价于省略
fn first_of<'a>(a: &'a str, b: &'a str) -> &'a str   // 等价写法
```

- 生命周期参数写在函数名后的 `<>` 里，可以和类型参数混用：`fn f<'a, T>(...)`
- 命名惯例是小写短名：`'a`、`'b`、`'de`、`'src`
- `'_` 表示"这里由编译器按省略规则补全"，常用于返回值或 `impl` 头

### 8.2 方法

```rust
impl<'a> Excerpt<'a> {
    fn part(&self) -> &str { self.part }           // 规则 3：输出借用 self
    fn replace(&mut self, new: &'a str) { self.part = new; }
}
```

- `&self` 方法的返回值默认绑定到 `&self`，而不是结构体的 `'a`
- 如果确实想返回结构体级别的 `'a`，要显式写 `fn part(&self) -> &'a str`
  （前提是字段确实是 `&'a str`）

### 8.3 结构体与枚举

```rust
struct Excerpt<'a> { part: &'a str }
enum Token<'a> {
    Word(&'a str),
    Number(u32),
}
```

- 每个存引用的字段都要有一个生命周期参数覆盖
- 结构体一旦带生命周期，所有使用处都要写：`Excerpt<'a>`、`Excerpt<'_>`
- 如果字段全是拥有者（`String`、`Vec`），就不需要生命周期参数

### 8.4 `'static` 相关写法

```rust
static GREETING: &str = "hello";       // 类型是 &'static str
const APP_NAME: &str = "daily-rust";   // 常量字符串也是 &'static str

fn keep<T: 'static>(value: T) -> T { value }

let boxed: Box<dyn std::fmt::Display> = Box::new(42);        // + 'static
let borrowed: Box<dyn std::fmt::Display + '_> = Box::new(&42); // 允许短借用
```

### 8.5 生命周期约束

```rust
fn pick<'a, 'b: 'a>(x: &'a str, y: &'b str) -> &'a str   // 'b: 'a
fn store<T: 'a>(value: T) -> T                            // T: 'a
```

- `'a: 'b`：`'a` 比 `'b` 活得更久（每个属于 `'b` 的程序点都属于 `'a`）
- `T: 'a`：类型 `T` 的所有借用都至少活到 `'a`

### 8.6 返回 `impl Trait` 时的生命周期

```rust
fn words<'a>(text: &'a str) -> impl Iterator<Item = &'a str> + 'a {
    text.split_whitespace()
}
```

- 返回值实现了 `Iterator`，且元素借用 `text`
- `+ 'a` 表示返回的迭代器本身也不能比 `'a` 活得更久
- edition 2024 的 `impl Trait` 默认捕获所有在作用域内的生命周期；
  旧 edition 需要显式 `+ 'a`

### 8.7 Trait 对象

```rust
&'a dyn Trait            // 借用的 trait 对象
Box<dyn Trait + 'a>      // 拥有的 trait 对象，允许短生命周期
Box<dyn Trait>           // 默认 = Box<dyn Trait + 'static>
```

## 三、实际应用与最佳实践

### 9.1 返回借用片段：零拷贝

```rust
fn first_word(text: &str) -> &str {
    text.split_whitespace().next().unwrap_or("")
}
```

返回的是原字符串的切片，不分配、不复制。这类函数的签名因为只有一个输入，
靠省略规则就能表达清楚关系。

### 9.2 零拷贝解析器：结构体借用输入

```rust
struct KeyValue<'a> { key: &'a str, value: &'a str }

fn parse_pair(line: &str) -> Option<KeyValue<'_>> {
    let (key, value) = line.split_once('=')?;
    Some(KeyValue { key, value })
}
```

`KeyValue` 不拥有字符串，解析一次 `line` 就得到两个片段。`Option<KeyValue<'_>>`
里的 `'_` 表示"输出借用 `line`"，调用方必须在 `line` 还活着时使用结果。

### 9.3 `Cow<'a, B>`：借用或拥有

```rust
fn normalize<'a>(input: &'a str) -> Cow<'a, str> {
    if input.contains(' ') {
        Cow::Owned(input.replace(' ', "_"))   // 需要修改才分配
    } else {
        Cow::Borrowed(input)                  // 能借就借
    }
}
```

`Cow` 是"写时复制"的经典类型：大多数情况零分配，需要修改时才拥有数据。
解析、配置合并、字符串清洗里非常常见。

### 9.4 返回借用输入的迭代器

```rust
fn words<'a>(text: &'a str) -> impl Iterator<Item = &'a str> + 'a
```

比返回 `Vec<&str>` 少了分配；调用方 `collect()` 时再决定要不要拥有。

### 9.5 API 设计：让返回值只依赖一个输入

- 返回借用时，尽量让它只依赖**一个**参数，省略规则就能表达，签名最简单
- 需要依赖多个输入时，显式 `'a` 把它们绑在一起，但调用方必须让所有输入都活够长
- 如果函数需要"返回新数据"，直接返回 `String`/`Vec<T>`，不要为了省一次分配
  硬凑生命周期——`Cow` 是折中方案

### 9.6 最佳实践清单

1. **先让编译器推断**：只在签名/结构体字段里写生命周期，函数体里不要标注
2. **优先省略**：单输入、`&self` 方法都能省略，别写多余的生命周期参数
3. **返回借用只依赖一个参数**，API 最稳定、调用方最省心
4. **结构体存引用要谨慎**：多数业务结构体应拥有数据；零拷贝解析器才值得带 `'a`
5. **`'static` 只用于真正的全局数据**（字面量、`static`、配置常量），
   不要给普通函数参数加 `'static`
6. **区分 `&'static T` 与 `T: 'static`**：前者是引用寿命，后者是"不含短借用"
7. **`Box<dyn Trait>` 默认 `'static`**：需要短借用时写 `Box<dyn Trait + 'a>`
8. **临时值先绑定再借用**，不要依赖生命周期扩展的复杂形式
9. **跨线程要求 `'static`**：优先转移所有权，确实要借用时用 scoped threads
10. **报错看不懂时查型变**：`&mut T`/`Cell<T>` 的不变性常是"不能缩短"的根源

## 常见陷阱

1. **多输入返回借用不标注（E0106）**：`fn f(a: &str, b: &str) -> &str`；
   改成 `fn f<'a>(a: &'a str, b: &'a str) -> &'a str`，或返回拥有所有权的值
2. **返回局部变量的引用（E0515）**：`fn f(x: &str) -> &str { let s = String::new(); &s }`；
   返回 `String` 或把结果写进调用方传入的 `&mut String`
3. **借用活不够长（E0597）**：把 `&local` 传给要求 `'static` 的函数、
   把借用存进生命周期更长的结构体
4. **结构体字段漏写生命周期（E0106）**：`struct S { part: &str }`；
   写成 `struct S<'a> { part: &'a str }`
5. **`'static` 滥用到参数**：`fn f(s: &'static str)` 让调用方无法传 `&String`；
   绝大多数情况写 `fn f(s: &str)` 就够
6. **`Box<dyn Trait>` 默认 `'static`**：捕获短借用时编译失败；
   写 `Box<dyn Trait + 'a>` 或先转成拥有所有权的值
7. **误以为 `String` 是 `&'static str`**：`String` 满足 `'static` 约束，
   但它的借用 `&s` 只在 `s` 活着时有效
8. **临时值借用（E0716）**：`let r = make().as_str();`；
   先 `let s = make(); let r = s.as_str();`
9. **`&mut` 的不变性**：`&'a mut &'b T` 不能随意改成 `&'a mut &'static T`；
   需要重新借用或调整结构
10. **在函数体里硬写生命周期**：局部变量的生命周期由借用检查器推断，
    显式标注通常只会让代码更难改
11. **返回借用参数的闭包**：闭包捕获局部变量后返回，生命周期无法逃逸；
    返回拥有所有权的值或使用 `move`
12. **自引用结构体**：字段借用自己的另一个字段，安全 Rust 无法直接构造；
    用索引/拥有数据，或使用 `Pin`（第 37 课）
13. **`impl Trait` 生命周期捕获**：edition 2024 会捕获所有在作用域的生命周期，
    旧代码迁移时可能需要在返回类型上补 `+ 'a`
14. **把生命周期当成"运行时检查"**：它完全在编译期完成，运行期没有任何开销

`&self` 省略、双生命周期字段、`static` 项、`'_` 占位符，最后用零拷贝解析、
`Cow`、返回借用迭代器和静态配置收尾。

   没有句号时返回整段。

4. 复现 E0106（多输入返回借用），分别用"显式 `'a`"和"返回 `String`"两种方式修复，
   比较两者的分配行为。
5. 实现 `normalize` 的 `Cow` 版本，分别测试"无需修改"和"含空格"两条路径，

   再改写成返回 `String` 的版本。
