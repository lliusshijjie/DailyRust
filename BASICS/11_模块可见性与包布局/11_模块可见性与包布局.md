# 第 11 课 · 模块、可见性与包布局

> 所需工具链：rustc 1.85+（edition 2024） ｜ 讲解：本文件 ｜ 独立代码：`11_modules_and_visibility.rs`

## 一、底层原理

### 11.1 包、crate、模块：三个层级

Rust 的项目结构有三层，先分清它们：

| 层级 | 是什么 | 边界 |
|---|---|---|
| **包（package）** | 一个 `Cargo.toml` 管理的项目 | 可以包含多个 crate |
| **crate** | 一次编译单元 | 一个 crate 一个根模块；二进制或库 |
| **模块（module）** | crate 内的命名空间 + 隐私边界 | 用 `mod` 显式声明，构成树 |

- **包**：`Cargo.toml` + `src/`，可以同时有 `src/lib.rs`（库 crate）和 `src/main.rs`（二进制 crate）
- **crate**：`main.rs` 是二进制 crate 的根；`lib.rs` 是库 crate 的根。二进制要用同包的库，
  需要 `use 包名::...`
- **模块**：不是文件系统自动发现的，必须在父模块里用 `mod` 声明，形成一棵显式的树

```rust
// src/main.rs —— crate 根
mod geometry;          // 声明子模块，对应 src/geometry.rs
mod store;             // 对应 src/store/mod.rs 或 src/store.rs

fn main() {
    let c = geometry::shapes::Circle::new(1.0);
}
```

`crate::` 指当前 crate 根，`super::` 指父模块，`self::` 指当前模块，`Self` 指当前类型。
路径写清楚，读代码时不需要知道模块树长什么样。

### 11.2 模块树与文件系统的映射

`mod foo;` 的查找规则：

```
src/foo.rs            ← 推荐（2018 之后）
src/foo/mod.rs        ← 也支持（老风格）
```

两者**不能同时存在**（否则报错）。子模块同理：

```
src/geometry.rs            // mod geometry;
src/geometry/shapes.rs     // 在 geometry.rs 里写 pub mod shapes;
```

内联模块（`mod foo { ... }`）和文件模块可以混用；文件只是模块内容的一种载体，
**模块树由 `mod` 声明决定**，不是"目录里有什么就编译什么"。

一个典型的包布局：

```
my_app/
├── Cargo.toml
├── build.rs                 # 可选：构建脚本
├── src/
│   ├── main.rs              # 二进制 crate 根
│   ├── lib.rs               # 库 crate 根（可选）
│   ├── geometry.rs          # mod geometry;
│   ├── geometry/
│   │   └── shapes.rs        # pub mod shapes;
│   └── bin/
│       └── tool.rs          # 额外的二进制入口
├── tests/
│   └── integration.rs       # 集成测试：独立 crate，只能用公开 API
├── examples/
│   └── demo.rs              # cargo run --example demo
└── benches/
    └── bench.rs             # cargo bench
```

- `src/bin/*.rs` 每个文件是一个独立二进制 crate
- `tests/*.rs` 每个文件是独立 crate，以"外部使用者"身份链接你的库——只能访问 `pub` API
- `examples/`、`benches/` 同理，都是独立 crate
- 单元测试写在模块内部的 `#[cfg(test)] mod tests`，可以访问私有项

### 11.3 可见性：默认私有，方向是"向下"

Rust 的默认可见性是**私有**：只有当前模块及其**后代模块**能访问。

| 写法 | 可见范围 |
|---|---|
| `fn f()`（无修饰） | 当前模块及其后代 |
| `pub` | 任何地方（受所在模块的可见性约束） |
| `pub(crate)` | 当前 crate 内任意模块 |
| `pub(super)` | 父模块及其后代 |
| `pub(in crate::a::b)` | 指定祖先模块 `a::b` 及其后代 |
| `pub(self)` | 等价于私有 |

方向的直觉：

```
crate
└── a
    ├── private_a      // a 及其后代可见
    └── b
        └── f          // a 看不到 b 的私有项
```

- **子模块能看祖先的私有项**（`b` 能读 `a` 的私有项）
- **祖先不能看子模块的私有项**（`a` 不能读 `b` 的私有项）
- `pub(super)` 让 `b` 里的项对 `a` 可见，但对 `a` 的父级不可见
- `pub(in crate::a)` 与 `pub(super)` 在两级结构里等价，多级时用来精确指定祖先

### 11.4 字段、枚举与 trait 的可见性

- **结构体字段独立于结构体**：`pub struct S { pub x: i32, y: i32 }` 里 `y` 仍是私有的，
  外部不能读、不能构造（E0616）
- **元组结构体字段**逐个标注：`pub struct Id(pub u64, u32)`
- **枚举变体继承枚举的可见性**：枚举是 `pub`，所有变体都可用；变体字段不能单独加 `pub`
- **trait 项没有可见性修饰符**：trait 是 `pub` 时，它的方法就是公开契约；
  impl 里的方法也不能私有
- `pub use` 的可见性不能超过被重导出项的可见性（否则 E0603）

### 11.5 路径与 `use`

```rust
use crate::geometry::shapes::Circle;       // 绝对路径
use crate::geometry::shapes::{Circle, unit};
use crate::geometry::shapes::Circle as C;  // 别名
pub use crate::geometry::shapes::Circle;   // 重导出
```

重要规则（2018 edition 起）：

- `use` 路径默认从 **crate 根**或 extern crate 开始；在子模块里写 `use foo::Bar`
  会去找 crate 根下/外部的 `foo`，找兄弟模块要写 `crate::foo::Bar` 或 `super::foo::Bar`
- `use` 只影响名字解析，不改变可见性；`pub use` 才会把名字暴露给外部
- `use` 可以写在函数内部，把导入限制在局部
- 通配导入 `use foo::*;` 会污染命名空间、隐藏依赖来源，工程代码里应避免
- `pub use` 是 API 设计工具：内部模块可以很深，对外只暴露一个扁平的门面

### 11.6 测试与可见性

```rust
#[cfg(test)]
mod tests {
    use super::*;          // 单元测试：能访问父模块私有项

    #[test]
    fn area_works() { ... }
}
```

- **单元测试**在模块内部，能测私有函数；`cargo test` 编译时才会包含
- **集成测试**在 `tests/` 下，是独立 crate，只能调用 `pub` API，等价于真实用户
- `#[cfg(test)]` 的代码不会进入发布构建

### 11.7 包布局与 Cargo

- `cargo new app`：默认二进制；`cargo new --lib libname`：库
- 包名里的 `-` 在 crate 名里变成 `_`（`my-app` → `my_app`）
- 同一包可以同时有 `lib.rs` 和 `main.rs`：库给外部用，二进制可 `use my_app::...`
- `Cargo.toml` 的 `[dependencies]` 引入外部 crate；`features` 控制可选功能（第 29 课）
- workspace 把多个包放在一个 `Cargo.toml` 下统一管理（第 29 课）

## 二、具体语法

### 12.1 声明模块

```rust
// 内联
mod math {
    pub fn add(a: i32, b: i32) -> i32 { a + b }
}

// 文件：src/math.rs 或 src/math/mod.rs
mod math;
```

- `mod` 是声明，不是"包含文件"；同一个模块树里不能重复声明
- 文件模块的内容直接成为该模块的项
- `#[path = "other.rs"] mod x;` 可以改路径，但会破坏约定，少用

### 12.2 路径

```rust
crate::math::add(1, 2);       // 从 crate 根
super::sibling();             // 父模块的项
self::helper();               // 当前模块的项
Self::new()                   // impl 里的当前类型
```

### 12.3 可见性修饰

```rust
pub fn public_api() {}
pub(crate) fn internal_only() {}
pub(super) fn parent_only() {}
pub(in crate::a) fn in_a() {}

pub struct Item {
    pub name: String,
    quantity: u32,            // 私有：只能通过方法访问
}
```

规则细则：

- `pub(in path)` 的 `path` 必须是当前项的**祖先模块**
- `pub(crate)` 不能出现在公开 API 的签名里"泄漏"内部类型（能编译，但设计上不好）
- 私有字段 + 公开方法是封装的默认写法；需要批量初始化时用构造器/`Default`

### 12.4 `use` 与重导出

```rust
use crate::store::inventory::Item;
use crate::store::inventory::{Item, Stock};
use crate::store::inventory::Item as InventoryItem;
pub use crate::store::inventory::Item;     // 门面
```

- `pub use` 后，外部可以 `use 包名::Item;`，不必知道 `store::inventory` 的层级
- 重复导出同名项会冲突，用 `as` 起别名
- `use` 只影响当前模块的名字解析；子模块不会自动继承父模块的 `use`

### 12.5 枚举与 trait 的可见性

```rust
pub enum Status { Active, Disabled }       // 变体随枚举公开
pub struct Id(pub u64, u32);               // 只有 .0 公开
```

- 枚举变体不能单独写 `pub`；要隐藏变体就隐藏整个枚举
- trait 方法天然是公开契约；实现类型的方法不能用 `pub(crate)` 收窄

### 12.6 文件布局

```rust
// src/main.rs
mod geometry;
mod store;
```

```rust
// src/geometry.rs
pub mod shapes;          // -> src/geometry/shapes.rs
```

```rust
// src/geometry/shapes.rs
pub struct Circle { ... }
```

## 三、实际应用与最佳实践

### 13.1 门面模块：隐藏内部层级

```rust
mod api {
    pub use crate::geometry::shapes::{unit, Circle};
    pub use crate::store::inventory::Item;
}
```

调用方只写 `api::Circle`、`api::Item`。以后内部把 `geometry::shapes` 拆成
`geometry::circle` + `geometry::polygon`，只要 `api` 的重导出不变，外部代码不用改。

### 13.2 私有字段 + 公开方法：守住不变量

```rust
pub struct Item {
    pub name: String,
    quantity: u32,
}

impl Item {
    pub fn quantity(&self) -> u32 { self.quantity }
    pub fn restock(&mut self, amount: u32) -> u32 { ... }
}
```

`quantity` 只能通过 `restock` 修改，库存不会变成非法值（比如溢出/负数）。
字段私有是封装的最小手段，比"约定不要直接改"可靠得多。

### 13.3 `pub(crate)` 做内部共享

```rust
pub(crate) fn crate_level() -> &'static str { "crate" }
```

多个内部模块需要共享工具函数，但不想暴露给外部用户时，用 `pub(crate)`。
`pub(super)` 更窄，只给父模块用；两者都不要出现在公开签名里。

### 13.4 批量使用与路径

```rust
let mut items = vec![api::Item::new("a", 2), api::Item::new("b", 3)];
let total: u32 = items.iter().map(|entry| entry.quantity()).sum();
```

门面 + 方法链让调用方读起来像普通 API，不关心模块层级。

### 13.5 最佳实践清单

1. **默认私有**，只有确实要对外的项才 `pub`
2. **字段私有 + 方法公开**，把不变量收进类型
3. **内部共享用 `pub(crate)`**，父模块专用用 `pub(super)`
4. **对外用 `pub use` 做门面**，隐藏内部模块路径
5. **模块按职责划分**，不要按文件类型机械拆分
6. **`use` 路径写全**：`crate::`/`super::`/`self::`，避免隐式相对路径
7. **避免通配导入**，显式列出依赖的名字
8. **单元测试放模块内**测私有逻辑，集成测试放 `tests/` 测公开 API
9. **包布局遵循 Cargo 约定**：`src/`、`tests/`、`examples/`、`benches/`
10. **把 `pub use` 当 API 承诺**：重导出的名字也会进入 semver 契约

## 常见陷阱

1. **文件存在但没 `mod` 声明**：编译器不会自动发现，文件被忽略；
   在父模块加 `mod foo;`
2. **`foo.rs` 与 `foo/mod.rs` 同时存在**：模块文件二义性错误；只保留一种
3. **子模块里 `use foo::Bar` 找不到兄弟模块（E0432）**：2018 起 `use` 路径从 crate 根开始，
   写 `use crate::foo::Bar;` 或 `use super::foo::Bar;`
4. **访问私有项（E0603）**：父模块/兄弟模块不能访问子模块私有项；
   加 `pub`/`pub(crate)`/`pub(super)`，或把访问逻辑放进子模块
5. **访问私有字段（E0616）**：结构体 `pub` 不代表字段 `pub`；
   给字段加 `pub` 或提供 getter/setter
6. **`pub use` 私有项（E0603）**：重导出的可见性不能超过原项；
   先把原项改成 `pub(crate)`/`pub`
7. **`pub(super)` 以为全 crate 可见**：它只到父模块；更外层要 `pub(crate)`
8. **`pub(in path)` 路径不是祖先**：编译错误；路径必须是当前模块的祖先
9. **枚举变体加 `pub`**：语法不允许；变体随枚举可见
10. **集成测试访问私有 API**：`tests/` 是独立 crate，只能看 `pub`；私有逻辑用单元测试
11. **通配导入导致名字冲突/来源不明**：显式 `use` 具体名字
12. **`main.rs` 直接引用 `lib.rs` 的模块**：它们是不同 crate，需要
    `use 包名::模块;`，不是 `mod` 引用
13. **`#[path]` 到处用**：破坏"文件即模块"的直觉，团队协作成本高
14. **模块名与文件名大小写不一致**：Windows 大小写不敏感、Linux 敏感，跨平台会炸
15. **`pub(crate)` 类型出现在 `pub` 函数签名里**：会触发 `private_interfaces` 警告
    （`-D warnings` 下失败），外部也无法命名该类型；公开 API 用 `pub` 类型
16. **`#[doc(hidden)]` 当私有**：它只是不在文档里显示，仍然可见；要隐藏就降可见性
17. **深层 `super::super::super`**：模块嵌套过深，考虑扁平化或用 `crate::` 绝对路径
18. **重导出造成循环/歧义**：`pub use` 链要单向，避免同名冲突

## 练习

1. 建一个 `math` 模块，内含 `add`/`sub`/`mul`，用 `pub use` 在 crate 根导出，
   外部只写 `math::add`。
2. 写 `bank` 模块：`Account` 的 `balance` 字段私有，只暴露 `deposit`/`withdraw`/`balance`；
   在 crate 根尝试直接读 `balance`，记录 E0616 并修复。
3. 设计三层模块 `outer::middle::inner`，分别用 `pub(crate)`、`pub(super)`、
   `pub(in crate::outer)` 暴露函数，验证各自能从哪一层调用。
4. 把示例里的内联模块改写成文件模块（`src/geometry.rs` + `src/geometry/shapes.rs`），
   用 `rustc main.rs` 编译并运行。
5. 给一个模块写 `#[cfg(test)] mod tests` 单元测试，再在 `tests/` 下写一个
   只调用 `pub` API 的集成测试，比较两者能访问的范围。
6. 设计一个库的门面：内部 3 个模块，对外只 `pub use` 两个类型和一个函数，
   并解释为什么这能降低 semver 风险。
7. 解释 `pub(crate)` 与 `pub(super)` 在两层结构和三层结构中的区别，各举一个例子。
