# 第 06 课 · 借用与可变借用

> 所需工具链：rustc 1.85+（edition 2024） ｜ 讲解：本文件 ｜ 独立代码：`06_borrowing_rules.rs`

## 一、底层原理

### 6.1 借用是"所有权的租借视图"

引用不拥有数据，它只是指向某个已有值的**借用**：

| 形式 | 名称 | 能做什么 | 同时存在几个 | 是否 Copy |
|---|---|---|---|---|
| `&T` | 共享借用 | 读 | 任意多个 | 是 |
| `&mut T` | 可变借用 | 读 + 写 | 同一时刻最多 1 个 | 否 |

借用检查器只有两条硬规则：

1. **别名 XOR 可变性**：任一时刻，要么有任意多个 `&T`，要么有唯一一个 `&mut T`，
   两者不能同时存在
2. **引用必须始终有效**：不能指向已经被移动/析构的值（无悬垂引用）

这两条规则在**编译期**由数据流分析保证，运行期没有任何检查成本——引用就是普通指针，
不需要引用计数。`Rc`/`Arc` 那种"运行期共享所有权"是另一套机制（第 05 课）。

### 6.2 为什么必须"别名 XOR 可变性"

这条规则同时解决三类问题：

- **迭代器失效**：持有 `&v[0]` 时 `v.push(...)` 可能重新分配缓冲区，
  旧引用立刻悬垂；编译器直接禁止
- **数据竞争**：多线程下 `&mut` 唯一 + `Send`/`Sync` 让"同时读写"无法通过编译（第 34 课）
- **别名 UB**：C/C++ 里两个指针指向同一块内存、其中一个被写，优化器可能给出反直觉结果

在机器码层面，`&mut T` 会被标记为 LLVM 的 `noalias`：编译器可以假设"这块内存只通过
这个引用访问"，从而把它保持在寄存器里、重排读写顺序。这让 Rust 的借用规则不只是
"安全"，还是**性能**来源。

对比 C 的 `restrict`：`restrict` 是程序员给编译器的**承诺**，违反它是未定义行为；
Rust 的规则由编译器**强制**检查，没有"承诺了但没做到"的空间。

需要"通过 `&T` 也能修改"时，标准库提供了受控的逃生舱——内部可变性：
`Cell`（复制进出、无检查）、`RefCell`（运行期借用检查）、`Mutex`（跨线程加锁），
见第 41 课。那是用运行期检查换编译期灵活性，而不是绕过规则。

### 6.3 NLL：借用在最后一次使用处结束

早期 Rust 的借用是"词法作用域"的：借用一直持续到所在块结束。Rust 2018（1.31）起
启用 **NLL（non-lexical lifetimes）**：借用持续到**最后一次使用**为止。

```rust
let mut v = vec![1, 2, 3];
let first = &v[0];
println!("{}", first);   // first 的最后一次使用
v.push(4);               // 借用已结束，可以独占
```

如果 `first` 在 `push` 之后还会被使用，编译器就会报 E0502——NLL 只是让"没用的借用"
提前结束，并没有放宽别名规则。

NLL 仍有一些做不到的模式（例如"在循环里根据条件返回借用"这类控制流相关的
Problem Case #3），目前由 Polonius 项目推进；日常代码里遇到的多半是借用跨分支存活，
解决办法通常是缩短作用域或调整代码结构。

### 6.4 两阶段借用：`v.push(v.len())` 为什么能编译

方法调用 `v.push(v.len())` 里，接收者 `v` 需要 `&mut`，而参数 `v.len()` 又需要 `&`。
按别名规则这应该冲突，但编译器对**方法接收者**使用"两阶段借用"：

1. **预留（reserve）**阶段：先记下"等会儿要独占 `v`"，但暂时不激活
2. 参数求值阶段：`v.len()` 的共享借用可以正常进行
3. **激活（activate）**阶段：参数算完后，`&mut` 才真正生效

所以 `vec.push(vec.len())`、`map.insert(key, map.len())` 这类写法是合法的。
两阶段借用只适用于方法接收者等有限场景，不是通用的"先读后写"许可。

### 6.5 重借用（reborrow）

`&mut T` 不是 `Copy`，但把它传给函数时编译器会自动插入**重借用**：

```rust
let mut v = vec![1];
let r = &mut v;
add_one(r);      // 实际传的是 &mut *r，重借用生命周期更短
add_one(r);      // r 仍然可用
```

显式写法是 `&mut *r`。重借用的生命周期只覆盖这次调用，所以原引用在调用结束后
重新变得可用。这也是"可变引用可以反复传给函数"的原因。

### 6.6 不相交借用（disjoint borrows）

借用检查器能识别**互不重叠**的借用：

```rust
let left = &mut pair.left;      // 不同字段，可以同时可变借用
let right = &mut pair.right;

let [a, b] = &mut arr;          // 数组元素拆开
let (a, b) = slice.split_at_mut(2);  // 切片拆成两段
```

但**运行期下标**不行：`&mut v[i]` 和 `&mut v[j]` 会被拒绝，因为编译器无法证明
`i != j`。这是借用检查器的保守之处，解决办法是用 `split_at_mut`、`iter_mut`、
`swap` 等"把不重叠性写进类型"的 API。

### 6.7 借用与函数边界

- `fn f(v: &T)` / `fn f(v: &mut T)`：调用方保留所有权，函数只借用
- 函数返回引用时，必须能证明被引用的数据活得更久（生命周期，第 07 课）
- `&'static T` 指向静态数据或泄漏的数据，生命周期是整个程序
- 把 `&mut` 存进结构体需要显式生命周期参数（第 07 课），大多数时候应存所有权

### 6.8 借用检查的错误家族

| 错误码 | 含义 | 典型场景 |
|---|---|---|
| E0502 | 已有共享借用，不能再可变借用 | `let r = &v[0]; v.push(1); use(r);` |
| E0499 | 同一时刻两个可变借用 | `let a = &mut v; let b = &mut v;` |
| E0506 | 借用期间赋值 | `let r = &x; x = 6; use(r);` |
| E0505 | 借用期间移动 | `let r = &s; drop(s); use(r);` |
| E0596 | 对不可变绑定取 `&mut` | `let x = 5; let r = &mut x;` |
| E0716 | 临时值在借用结束前被丢弃 | `let r = make().as_str();` |

## 二、具体语法

### 7.1 创建、解引用与自动解引用

```rust
let mut value = 10;
let shared = &value;        // &i32
let exclusive = &mut value; // &mut i32
*exclusive += 5;            // 解引用后修改
```

- `&expr` / `&mut expr` 创建借用；`*r` 解引用
- 方法调用会自动解引用：`r.push(x)` 等价于 `(*r).push(x)`（必要时再自动取引用）
- `&mut T` 可以强制转换为 `&T`（只读视图），反向不行：
  `let s: &i32 = exclusive;`

### 7.2 共享引用的 Copy 与可变引用的重借用

```rust
let a = 42;
let r1 = &a;
let r2 = r1;              // &T 是 Copy，r1 仍可用
println!("{} {}", r1, r2);

let mut v = vec![1];
let r = &mut v;
add_one(r);               // 自动重借用
add_one(r);
```

- 共享引用复制后指向同一地址（`std::ptr::eq(r1, r2)` 为 `true`）
- 可变引用赋值会移动它：`let r2 = r;` 之后 `r` 不可用；
  要同时保留两个"入口"必须显式重借用 `&mut *r`

### 7.3 方法接收者：`&self` / `&mut self`

```rust
impl Counter {
    fn value(&self) -> i32 { self.value }          // 只读
    fn increment(&mut self) { self.value += 1; }   // 修改
    fn into_value(self) -> i32 { self.value }      // 消费（第 05 课）
}
```

方法签名直接决定调用时是共享借用、可变借用还是移动。这是 Rust API 设计的核心表达手段
之一（第 08 课展开）。

### 7.4 切片与分段可变借用

```rust
let mut data = [1, 2, 3, 4];
let (left, right) = data.split_at_mut(2);   // 两段互不重叠的 &mut [i32]
left[0] = 10;
right[0] = 30;

for element in &mut data {                  // 可变迭代
    *element *= 2;
}
```

- `split_at_mut` 是"同时修改两段"的标准答案
- `chunks_mut(n)` 按块切分、`chunks_exact_mut` 丢弃末尾不足块
- `&mut data[1..3]` 是子切片；越界会 panic

### 7.5 迭代与借用

| 写法 | 元素类型 | 所有权 |
|---|---|---|
| `for x in &v` | `&T` | 只借用 |
| `for x in &mut v` | `&mut T` | 可变借用 |
| `for x in v` | `T` | 移动/消费 `v` |
| `v.iter()` | `Iterator<Item = &T>` | 只借用 |
| `v.iter_mut()` | `Iterator<Item = &mut T>` | 可变借用 |

循环结束后借用即失效，可以继续使用原变量（NLL）。如果在循环里同时持有元素引用并修改容器，
就会触发 E0502。

### 7.6 模式匹配里的 `&mut`

```rust
let mut slot = Some(5);
if let Some(inner) = &mut slot {
    *inner += 1;                 // inner: &mut i32
}

let mut text = Some(String::from("s"));
if let Some(s) = text.as_mut() { // as_mut() 把 Option<T> 借成 Option<&mut T>
    s.push('!');
}
```

- `match &mut opt { Some(x) => ... }` 里的 `x` 是 `&mut T`（match ergonomics，第 09 课）
- `Option::as_ref` / `as_mut` 把所有权容器借成引用容器
- `&mut` 模式要求被匹配的绑定本身可变

### 7.7 Deref 强制转换

```rust
fn first_char(text: &str) -> char { ... }

let owned = String::from("rust");
first_char(&owned);              // &String -> &str
```

`&String` → `&str`、`&Vec<T>` → `&[T]`、`&Box<T>` → `&T` 都是自动的（Deref coercion）。
这是"函数参数用 `&str`/`&[T]`"能同时接受 `String`/`Vec` 的原因（第 04 课）。

## 三、实际应用与最佳实践

### 8.1 就地修改：`&mut [T]` 而不是"克隆—修改—返回"

```rust
fn scale(values: &mut [i32], factor: i32) {
    for value in values {
        *value *= factor;
    }
}

let mut data = [1, 2, 3];
scale(&mut data, 3);      // [3, 6, 9]
```

不分配、不克隆，调用方保留所有权。标准库的 `sort`、`reverse`、`fill`、`rotate_left`
等都是这个形状。

### 8.2 结构体方法：用接收者表达权限

```rust
let mut counter = Counter::new();
counter.increment();       // &mut self
counter.increment();
println!("{}", counter.value());  // &self
```

- 查询方法用 `&self`，修改方法用 `&mut self`，需要交出内部所有权时用 `self`
- 方法签名写清楚后，调用方在编译期就知道"这次调用会不会改变对象"

### 8.3 分段处理：`split_at_mut` 替代"两次下标"

```rust
let (first_three, last_three) = values.split_at_mut(3);
first_three.sort();
last_three.sort();
```

如果写成 `values[0..3].sort(); values[3..].sort();` 也可以，但一旦需要**同时**持有
两段的引用（比如并行处理、互相引用），只有 `split_at_mut` 能通过借用检查。

### 8.4 就地反转与交换

```rust
let mut letters = ['a', 'b', 'c'];
letters.reverse();        // ['c', 'b', 'a']
letters.swap(0, 2);       // 交换两个元素
```

`swap` 是"运行期下标"场景的安全出口：它内部用 `unsafe` 证明 `i != j` 时的
两个可变借用是合法的，外部 API 完全安全。

### 8.5 借用写入：调用方保留所有权

```rust
let mut output = String::new();
append_all(&mut output, &["a", "b"]);
println!("{}", output);   // ab
```

"输出参数"在 Rust 里通常写成 `&mut T`，但更推荐直接返回新值（第 05 课的移动很便宜）；
只有在需要复用已有分配（比如大 `String` 缓冲区）时，`&mut` 才有明显收益。

### 8.6 借用冲突的常见解法

| 冲突 | 解法 |
|---|---|
| 持有元素引用时修改容器 | 先完成读、再修改；或 `split_at_mut` |
| 两个 `&mut` 指向同一容器 | 缩小作用域、`split_at_mut`、`iter_mut` |
| 需要同时读写同一字段 | 拆字段（`&mut s.a`, `&mut s.b`） |
| 结构体方法里借用了 `self` 又要改 `self` | 先取出所需数据、或 `mem::take` |
| 边遍历边删元素 | `retain`、`drain`、`swap_remove`（第 20 课） |
| 跨线程共享可变状态 | `Mutex`/`RwLock`/原子类型（第 33、35 课） |

### 8.7 最佳实践清单

1. **默认 `&T`**，只有确实要修改时才用 `&mut T`
2. **函数参数用 `&[T]`/`&str`**，让调用方决定是否给 `Vec`/`String`
3. **让方法接收者表达意图**：`&self` 查询、`&mut self` 修改、`self` 消费
4. **缩小借用作用域**：能在一个表达式/语句里用完的借用，不要拖到块尾
5. **同时改两段用 `split_at_mut`**，不要写两次 `&mut v[i]`
6. **运行期下标 + 可变借用**优先用 `swap`/`iter_mut`/`split_at_mut`
7. **不要为了绕开借用检查而 `clone`**：先想清楚数据的生命周期，clone 只应作为最后手段
8. **需要内部可变性时**才用 `Cell`/`RefCell`，并接受运行期检查的成本
9. **借用与所有权分离**：把"数据"和"对数据的临时访问"分开设计，API 会更自然
10. **理解 E0502/E0499 的错误文本**，它通常会直接告诉你哪个借用还没结束

## 常见陷阱

1. **同时持有 `&` 和 `&mut`（E0502）**：持有 `&v[0]` 时 `v.push()`，
   且之后再使用 `&v[0]`——NLL 也救不了
2. **两个 `&mut`（E0499）**：`let a = &mut v; let b = &mut v;`；
   用重借用 `&mut *a` 或 `split_at_mut`
3. **借用期间赋值（E0506）**：`let r = &x; x = 6; println!("{}", r);`
4. **借用期间移动（E0505）**：`let r = &s; drop(s);`——值被移走，借用悬垂
5. **对不可变绑定取 `&mut`（E0596）**：`let x = 5; let r = &mut x;`
6. **误以为 `&mut` 是 Copy**：`let r2 = r;` 之后 `r` 已失效；要重复使用写 `&mut *r`
7. **边遍历边修改容器**：`for x in &v { v.push(...) }` 直接 E0502；
   用下标循环、`retain` 或先收集再处理
8. **临时值借用（E0716）**：`let r = make().as_str();`——临时 `String` 在语句结束就释放；
   先 `let s = make(); let r = s.as_str();`
9. **闭包同时可变捕获**：两个闭包都 `&mut` 捕获同一个变量会冲突；
   用 `RefCell` 或调整闭包边界
10. **在结构体方法里同时 `&self` 和 `&mut self`**：例如 `self.update(self.read())`
    可能冲突；先取值到局部变量
11. **返回局部变量的引用**：`fn f() -> &str { &String::from("x") }` 编译失败；
    要么返回所有权，要么借用参数（第 07 课）
12. **索引两次可变借用**：`&mut v[i]` 与 `&mut v[j]` 冲突，即使用 `i != j` 的运行时检查；
    改用 `split_at_mut`/`swap`
13. **误以为 NLL 能解决所有问题**：借用跨分支存活时仍会报错，需要重构控制流
14. **`RefCell` 运行期 panic**：内部可变性把冲突从编译期推迟到运行期，
    双重 `borrow_mut` 会 panic（第 41 课）

## 练习

1. 实现 `fn rotate_left(values: &mut [i32], n: usize)`，只用 `&mut [T]` 和原地交换，
   不允许分配新 `Vec`。
2. 写一个 `Counter`，提供 `increment(&mut self)`、`value(&self)`、`reset(&mut self)`，
   并解释为什么 `value` 不能用 `&mut self`（提示：调用方的并发/只读意图）。
3. 用 `split_at_mut` 实现 `fn add_halves(values: &mut [i32])`：
   前半段加上后半段对应元素（长度取较短者），要求只借用一次。
4. 复现 E0502：先 `let r = &v[0];` 再 `v.push(1);` 再使用 `r`，
   记录完整错误信息；然后用"先读后改"和 `split_at_mut` 两种方式修复。
5. 解释：为什么 `v.push(v.len())` 能编译，而 `let r = &v; v.push(1); use(r);` 不能？
6. 写 `fn first_word(text: &str) -> &str` 返回第一个单词（提示：生命周期省略规则，
   第 07 课会解释为什么这样写能通过）。
