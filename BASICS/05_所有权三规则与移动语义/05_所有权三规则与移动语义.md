# 第 05 课 · 所有权三规则与移动语义

> 所需工具链：rustc 1.85+（edition 2024） ｜ 讲解：本文件 ｜ 独立代码：`05_ownership_and_move.rs`

## 一、底层原理

### 5.1 所有权是编译期分析，不是运行期字段

Rust 的所有权只有三条规则：

1. 每个值都有且只有一个**所有者**（owner）
2. 同一时刻，一个值只能有一个所有者
3. 所有者离开作用域时，值被**析构**（drop）

关键在于：所有权**不占任何运行时存储**。编译器在 MIR 上做一次数据流分析，
追踪每个值的状态（已初始化 / 已移动 / 已借用），在作用域结束时插入
"析构胶水代码"（drop glue）。所以：

- 没有 GC、没有引用计数（`Rc`/`Arc` 除外），析构时机是**确定**的
- 移动、借用、生命周期检查全部在编译期完成，运行时零成本
- "use after move" 是编译错误，而不是运行时崩溃

| 语言 | 内存回收 | 悬垂/重复释放 | 运行时成本 |
|---|---|---|---|
| C/C++ | 手动 `new`/`delete` | 可能发生（UB） | 无 |
| Java/Go | GC | 不会 | GC 停顿、额外内存 |
| Rust | 编译期所有权 + 确定性 drop | 编译期拒绝 | 无 |

### 5.2 移动 = 复制值的表示 + 源失效（不是 C++ 的移动构造）

Rust **没有移动构造函数**，也没有 `std::move`。所谓"移动"，在机器层面就是：

1. 把值本身复制到新位置（对 `String` 是复制 3 个机器字，对结构体可能是 memcpy）
2. 在编译期把源标记为"已移动"，此后源不可再用

因此移动**不调用源值的析构函数**，值只在最终所有者离开作用域时 drop 一次。
以 `String` 为例：

```
栈上（所有者）          堆上
┌──────────────┐      ┌──────────────┐
│ ptr  ────────┼─────▶│ heap buffer  │
│ len          │      └──────────────┘
│ cap          │
└──────────────┘
```

`let b = a;` 只复制这 24 字节的头部（8 字节指针 × 3），堆缓冲原地不动，
所以 `a.as_ptr() == b.as_ptr()`。这正是示例里 `same_heap_after_move=true` 的含义。

与 C++ 的对比：

| | C++ | Rust |
|---|---|---|
| 移动的触发 | `std::move` + 移动构造/赋值 | 赋值、传参、返回等自动发生 |
| 移动做了什么 | 用户代码决定（可窃取资源） | 复制值的表示，源在编译期失效 |
| 移动后源的状态 | 有效但未指定（需手动置空） | **编译期不可用** |
| 代价 | 取决于移动构造函数 | 与值大小成正比（`String` 是 3 个字） |

一个重要推论：**移动大结构体是 O(size) 的**。移动 `[u8; 1_000_000]` 会复制 1MB；
需要频繁移动大对象时，用 `Box<T>` 把大头放到堆上，移动的只是一个指针。

### 5.3 `Copy`：按位复制，双方都有效

`Copy` 是一个标记 trait，表示"这个类型可以按位复制"：

- 约束：`Copy: Clone`；自己实现 `Drop` 的类型**不能** `Copy`（E0184）
- 一个结构体/枚举的所有字段都 `Copy` 时，才能 `derive(Copy)`
- `Copy` 类型在赋值、传参、返回时执行复制，源和目标都继续可用
- 常见的 `Copy` 类型：整数、浮点、`bool`、`char`、共享引用 `&T`、裸指针、
  函数指针、`Copy` 元素的元组和数组
- 注意 `&mut T` **不是** `Copy`（可变引用必须独占，复制会破坏别名规则）

| | Copy | Clone | Move |
|---|---|---|---|
| 是否隐式 | 是 | 否（要写 `.clone()`） | 是 |
| 源是否失效 | 否 | 否 | 是 |
| 代价 | 按位复制 | 用户定义（可能很深） | 复制值的表示 |
| 典型类型 | `i32`、`&T`、`[u8; 4]` | `String`、`Vec`、`Rc` | 所有非 `Copy` 类型 |

### 5.4 `Clone`：显式复制，代价可见

`Clone` 是"显式复制一份"的能力：

- `String`/`Vec` 的 `clone` 会**重新分配并复制堆数据**（深拷贝）
- `Rc`/`Arc` 的 `clone` 只是引用计数 +1（浅拷贝，共享同一份数据）
- `#[derive(Clone)]` 对每个字段调用 `clone`，所以"深不深"由字段决定
- `clone()` 写在代码里就是一个醒目的成本提示；`clone_from` 可以复用已有分配
- `Copy` 类型都实现 `Clone`，但 `Clone` 不蕴含 `Copy`

### 5.5 移动发生在哪些地方

只要"把一个值放到新位置"，就是移动（`Copy` 类型则是复制）：

| 场景 | 例子 |
|---|---|
| 赋值 | `let b = a;` |
| 函数传参（按值） | `consume(s);` |
| 函数返回 | `fn make() -> String` |
| 容器插入 | `vec.push(s);` |
| 结构体/元组构造 | `Request { url: s, .. }` |
| 解构非 `Copy` 值 | `let (a, b) = (s1, s2);` |
| `match` 按值绑定 | `match opt { Some(s) => ... }` |
| 闭包按值捕获 | `move \|\| s` |

### 5.6 部分移动与 `Drop` 的约束

- **部分移动**：从没有实现 `Drop` 的结构体里移出某个字段后，结构体整体不可再用，
  但**未移动的字段仍可访问**。这允许"拆包"式地消费数据
- 实现了 `Drop` 的类型**不能**部分移动（E0509）：析构函数需要完整值，
  编译器无法保证字段都还在
- **不能从借用中移动**（E0507）：`&T` 不拥有数据，只能 `clone`、`take`、`replace`
- 不能从索引中移动（E0508：`array[0]` 对非 `Copy` 元素），因为会在容器里留下洞

需要"从借用里拿走值"时，标准库提供了成套工具：

```rust
let taken = option.take();                 // 取出并留下 None
let old = mem::replace(&mut slot, new);    // 取出并换上新值
let value = mem::take(&mut field);         // 取出并留下 Default
mem::swap(&mut a, &mut b);                 // 交换两个位置
```

### 5.7 析构顺序：确定性的 drop 链

Rust 的析构顺序是规范保证的：

| 对象 | 顺序 |
|---|---|
| 同一作用域的局部变量 | **声明逆序**（后声明的先 drop） |
| 结构体字段 | **声明顺序** |
| 元组元素 | 声明顺序 |
| 数组元素 | 索引顺序（0 → n） |
| 自定义 `Drop` 的类型 | 先执行 `Drop::drop`，再析构字段 |

```rust
struct Outer { inner: Tag }
impl Drop for Outer {
    fn drop(&mut self) { println!("outer"); }   // 先打印
}
// 输出：outer，然后 tag inner
```

### 5.8 栈、堆与"所有权不是内存位置"

- `String`、`Vec`、`Box` 的所有者值在栈上只有一个小头部，真正的数据在堆上
- 移动所有者 = 移动头部；堆数据不动，也不需要重新分配
- `Rc<T>`/`Arc<T>` 把"所有权"扩展成"共享所有权 + 引用计数"：每次 `clone` 计数 +1，
  最后一个所有者 drop 时释放数据
- 借用（`&T`/`&mut T`）不拥有数据，生命周期由借用检查器保证（第 06、07 课）

## 二、具体语法

### 6.1 三条规则的代码形态

```rust
{
    let s = String::from("hi");   // s 是所有者
    // ...
}                                  // 作用域结束，s drop，堆缓冲释放
```

移动后源不可用（这段代码不能编译）：

```rust
let a = String::from("hi");
let b = a;
println!("{}", a);   // error[E0382]: use of moved value: `a`
```

`Copy` 类型不受影响：

```rust
let x = 7;
let y = x;
println!("{} {}", x, y);   // 7 7
```

### 6.2 `derive` 与手写实现

```rust
#[derive(Clone, Copy, Debug)]
struct Point { x: i32, y: i32 }        // 所有字段 Copy -> 可以 Copy

#[derive(Clone)]
struct Buffer(Vec<u8>);                 // 只能 Clone：Vec 不是 Copy

struct Handle(u32);
impl Clone for Handle { fn clone(&self) -> Self { Handle(self.0) } }
impl Copy for Handle {}                 // 手写 Copy：先有 Clone，再空 impl
```

规则细则：

- `derive(Copy)` 必须同时 `derive(Clone)`；手写 `impl Copy` 要求类型已实现 `Clone`
- 编译器会检查所有字段是否 `Copy`，有非 `Copy` 字段直接报错
- 实现了 `Drop` 的类型不能再 `Copy`（E0184）
- `Copy` 是"隐式、廉价、按位"的承诺，不要给带堆资源的类型实现

### 6.3 函数签名里的所有权

```rust
fn consume(text: String) -> usize;      // 拿走所有权
fn inspect(text: &String) -> usize;     // 只读借用
fn mutate(text: &mut String);           // 可变借用
fn borrow_and_return(text: &str) -> &str;  // 返回借用（需要生命周期，第 07 课）
```

- 调用 `consume(s)` 之后，调用方的 `s` 不可再用
- `inspect(&s)` 之后 `s` 仍可用
- 返回值的所有权交给调用方
- 按值传入再按值返回是"移动往返"，语义清晰但可能产生一次复制；
  编译器通常会优化掉，但语言不保证"一定零拷贝"

### 6.4 从借用/容器中取值

```rust
let mut slot = Some(String::from("x"));
let taken = slot.take();                   // Option<String>，slot 变 None

let mut field = String::from("old");
let old = std::mem::replace(&mut field, String::from("new"));
```

- `Vec::pop()` / `Vec::swap_remove(i)` / `Vec::remove(i)` 都把元素**移出**容器
- `HashMap::remove` 把值移出
- `Rc::try_unwrap` / `Arc::try_unwrap`：当引用计数为 1 时取回所有权
- `mem::take` 要求 `T: Default`；`mem::replace` 只需要新值

### 6.5 显式析构与"泄漏"

```rust
let s = String::from("bye");
drop(s);                  // 立即析构（本质是把它移进 drop 函数）
// println!("{}", s);     // 编译错误：已经 move 掉了

// 下面这种写法不合法：
// s.drop();              // 实现了 Drop 的类型会报 E0040（不能显式调用析构函数）
```

- `std::mem::drop` 只是 `fn drop<T>(_: T) {}`，靠"传参即移动"来提前释放
- `std::mem::forget(x)` 会跳过析构（安全但泄漏）；`Box::leak` 返回 `&'static mut T`
- `ManuallyDrop<T>` 用于需要手动控制析构时机的底层代码
- 程序正常退出时局部变量的析构会执行；`std::process::exit` 不会

### 6.6 移动与循环、条件分支

```rust
// 错误：第一轮就把 s 移走了，第二轮无法再移
// let s = String::from("x");
// for _ in 0..2 { drop(s); }

// 正确：在循环体内创建，每轮都是新的所有者
for _ in 0..2 {
    let s = String::from("x");
    drop(s);
}
```

条件分支里，编译器要求**每条通往使用点的路径**都保证值已初始化：

```rust
let mut state = String::from("first");
if cond {
    drop(state);
    state = String::from("second");   // 这条路径重新初始化
}
println!("{}", state);                // 两条路径都有效，编译通过
```

## 三、实际应用与最佳实践

### 7.1 让签名表达所有权意图

| 签名 | 语义 | 调用方之后 |
|---|---|---|
| `fn f(v: T)` | 消费 | 不能再用 `v` |
| `fn f(v: &T)` | 只读借用 | 仍可用 |
| `fn f(v: &mut T)` | 可变借用 | 仍可用，但借用期间不能有其他访问 |
| `fn f(v: T) -> T` | 消费后交还 | 用返回值替换 |

函数默认用 `&T`/`&[T]`；只有确实需要接管所有权（存入容器、跨线程转移、
消耗型 builder）时才按值传。

### 7.2 容器：push 进入、pop 出来

```rust
let mut queue = vec![String::from("a")];
queue.push(String::from("b"));     // 所有权移入
let popped = queue.pop().unwrap(); // 所有权移出
```

容器是所有权的"中转站"：元素的生命周期由容器管理，`remove`/`pop` 把所有权交回调用方。

### 7.3 消费型 builder

```rust
let request = Request::new("api.example.com").timeout(30);
```

每个方法拿走 `self` 并返回 `Self`，链式调用在类型上就是"逐步消耗并重建"。
好处是编译期就能防止"构建到一半又被别处使用"；代价是每次调用都有一次移动
（`Request` 只含 `String` + `u64`，移动很便宜）。

### 7.4 `Rc`/`Arc`：共享所有权

```rust
let doc = Rc::new(String::from("shared-doc"));
let doc2 = Rc::clone(&doc);       // 计数 2，不复制字符串
```

- `Rc<T>` 单线程共享；`Arc<T>` 多线程共享（`Rc` 不是 `Send`/`Sync`）
- 共享所有权是"最后一个人关灯"：计数归零才 drop 数据
- 循环引用会泄漏，需要 `Weak<T>` 打破环

### 7.5 `mem::take` 重置字段

```rust
let value = std::mem::take(&mut config.right);
// config.right 现在是 String::default()，config 本身仍可用
```

从 `&mut` 里"拿走"值但保留结构体，是状态机、连接复用、配置重置的常用手法。

### 7.6 最佳实践清单

1. **优先借用**：能 `&T` 就不按值传，能 `&[T]` 就不传 `Vec<T>`
2. **按值传参 = 明确消费**：让签名告诉调用方"这个值归我了"
3. **不要为通过编译而乱 `clone`**：先看能不能借用、`take`、`replace`
4. **大对象移动前先 Box 化**：移动 1MB 的数组是真的复制 1MB
5. **`Copy` 只给"位模式就是值"的类型**：带堆资源、带 `Drop` 的类型不要 `Copy`
6. **`Clone` 要显式**：让 `.clone()` 成为代码里的成本标记；热路径上尤其注意
7. **共享所有权用 `Rc`/`Arc`，并警惕循环引用**
8. **需要"取出但不销毁容器"时用 `take`/`replace`/`swap`**
9. **需要提前释放时用 `drop(x)`**，不要依赖作用域"碰巧结束"
10. **记住析构顺序**：局部逆序、字段声明顺序，写有副作用的 `Drop` 时要考虑清楚

## 常见陷阱

1. **use after move（E0382）**：`let b = a;` 之后再用 `a`。
   错误信息会指出"value moved here"和"value used here"
2. **从借用中移动（E0507）**：`fn f(v: &Vec<String>) { let s = v[0]; }`
   不能把 `&T` 里的值搬走；用 `clone`、`&v[0]` 或改成按值接收
3. **从实现了 `Drop` 的类型里部分移动（E0509）**：析构函数需要完整值，
   要么整体消费，要么用 `Option`/`mem::take` 把字段变成可替换的
4. **给带析构函数的类型实现 `Copy`（E0184）**：`Copy` 意味着"复制后两份都有效"，
   与"只能释放一次"矛盾
5. **`&mut T` 不是 `Copy`**：`let r2 = r;` 会把 `r` 移走；需要重新借用 `&mut *r`
6. **循环里移动外层变量**：第一轮就 move 走了，第二轮报 E0382；
   把创建移进循环体，或用 `&`/`clone`
7. **部分移动后使用整个结构体**：移动了 `pair.left` 之后，
   不能再把 `pair` 整体传参，只能使用未移动的字段
8. **`clone()` 放进热循环**：每次分配 + 复制，性能断崖式下降
9. **`Rc` 跨线程**：`Rc<T>` 不是 `Send`，跨线程要 `Arc<T>`（第 34 课）
10. **`mem::forget` 当"优化"**：它只是泄漏，不析构；不要用它逃避所有权检查
11. **显式调用析构函数**：`x.drop()` 不允许（E0040 或根本没有该方法），
    要提前释放就写 `drop(x)`
12. **大结构体按值传参**：每次调用复制整个结构体；用 `&T` 或 `Box<T>`
13. **`match` 分支按值绑定**：`match opt { Some(s) => ... }` 会把 `s` 移出来，
    之后 `opt` 不可用；需要保留就匹配 `&opt`
14. **返回局部变量的引用**：所有权随函数结束而释放，编译期报错；
    返回 `String`/`Vec` 或让生命周期绑定到参数（第 07 课）

## 练习

1. 实现一个基于 `Vec<T>` 的 `Queue<T>`，提供 `push`/`pop`/`peek`，
   并解释 `push`/`pop` 时元素所有权如何转移。
2. 写 `fn split_owned(text: String, at: usize) -> (String, String)`，
   要求不 panic；再写一个 `&str` 版本，比较两者的所有权差异。
3. 给一个带 `Drop` 的结构体尝试移出字段，记录 E0509 的完整错误信息，
   然后用 `Option<T>` 字段 + `take()` 改写它。
4. 用 `mem::replace` 实现"插入新值并返回旧值"的函数；
   再用 `mem::swap` 实现两个 `Vec<String>` 的交换。
5. 写一个消费型 builder（`HttpRequest`：url、method、timeout），
   并说明为什么链式调用后原变量不能再用。
6. 解释：为什么移动 `String` 不复制堆缓冲，而移动 `[u8; 1_000_000]` 会复制 1MB？
   分别给出适合的优化方式。
