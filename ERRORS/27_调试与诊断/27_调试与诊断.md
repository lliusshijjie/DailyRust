# 第 27 课 · 调试与诊断：dbg!、断言与 Debug

> 所需工具链：rustc 1.85+（edition 2024） ｜ 讲解：本文件 ｜ 独立代码：`27_debugging_and_assertions.rs`

## 一、底层原理

### 27.1 `dbg!`：带位置的临时调试输出

`dbg!(expr)` 会：

1. 求值 `expr`（只求值一次）
2. 把 `文件:行号`、表达式源码文本、`Debug` 值写到 **stderr**
3. **返回**这个值，所以可以嵌在表达式里

```rust
let value = 42;
let doubled = dbg!(value * 2) + 1;
// stderr: [src/main.rs:3:19] value * 2 = 84
// doubled = 85
```

关键细节：

- 输出目标是 **stderr**，不是 stdout；测试里需要 `--nocapture` 才能看到
- 打印的是 `Debug`（`{:?}`），不是 `Display`
- 路径与行号来自调用点，适合临时定位
- `dbg!(owned_string)` 会**移动** `owned_string`（虽然会返回它；如果返回值被丢弃，
  值就在语句结束 drop）；只看不拿走请写 `dbg!(&owned_string)`
- 生产代码里不要留 `dbg!`；clippy 有 `dbg_macro` lint 可以禁止
- 本课示例为了保持 stdout 确定、避免 stderr 里的中文路径，改用 `Debug` +
  断言消息演示同等诊断信息

### 27.2 `Debug`：给开发者看的结构化输出

```rust
#[derive(Debug)]
struct User {
    name: String,
    age: u32,
}

println!("{:?}", user);      // User { name: "alice", age: 30 }
println!("{:#?}", user);     // 多行美化
```

- `Debug` 是"开发者视角"：显示类型名、字段名、引号、转义
- `Display` 是"用户视角"：`{}`，需要手写，不能 derive
- `{:#?}` 是 pretty Debug：缩进、多行，适合排查而不是日志正文
- `derive(Debug)` 要求所有字段都实现 `Debug`
- Debug 输出**不是稳定格式**：不要解析它、不要把它当协议；版本升级可能变化

自定义 `Debug`：

```rust
impl fmt::Debug for Credentials {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        f.debug_struct("Credentials")
            .field("user", &self.user)
            .field("token", &"***")        // 脱敏
            .finish()
    }
}
```

`Formatter` 提供结构化构建器：

| 方法 | 用途 |
|---|---|
| `debug_struct("Name")` | 结构体 |
| `debug_tuple("Name")` | 元组结构体 |
| `debug_list()` | 列表 |
| `debug_set()` | 集合 |
| `debug_map()` | 映射 |
| `.finish()` | 结束 |
| `.finish_non_exhaustive()` | 打印 `..` 表示还有字段 |

### 27.3 断言：把不变量写成可执行检查

| 宏 | 何时检查 | 失败 |
|---|---|---|
| `assert!(cond, "msg")` | 永远 | panic |
| `assert_eq!(a, b)` | 永远 | panic，打印两边 |
| `assert_ne!(a, b)` | 永远 | panic，打印两边 |
| `debug_assert!(cond)` | 仅 debug 构建 | panic |
| `debug_assert_eq!` | 仅 debug 构建 | panic |

`assert_eq!` 失败输出（Rust 1.92，格式可能随版本微调）：

```
assertion `left == right` failed
  left: 3
 right: 4
```

注意 `left` 与 `right` 的对齐空格不同；**不要写代码解析这个格式**，它只是给人看的。

- `assert!` 在 release 也执行；`debug_assert!` 在 release 被移除
- `debug_assert!` 里的**副作用也会被移除**：不要把必要逻辑放进去
- `assert_eq!` 要求 `PartialEq + Debug`；自定义类型记得 `derive(Debug, PartialEq)`
- 消息里带上实际值：`assert!(age <= 150, "age out of range: {age}")`

### 27.4 位置、调用者与 `#[track_caller]`

- `file!()`、`line!()`、`column!()` 在编译期展开
- `std::panic::Location::caller()` 返回调用点位置
- `#[track_caller]` 让自定义包装函数把"调用者位置"传给 panic/日志

```rust
#[track_caller]
fn require_positive(value: i32) {
    assert!(value > 0, "must be positive: {value}");
}

require_positive(-1);
// panic 位置指向 require_positive 的调用行，而不是函数内部
```

标准库的 `unwrap`/`expect` 都带 `#[track_caller]`，所以错误位置指向调用行。

### 27.5 回溯（backtrace）

- 设置 `RUST_BACKTRACE=1` 后，panic 会打印回溯
- `std::backtrace::Backtrace::capture()` 遵循环境变量；
  `force_capture()` 忽略环境变量
- `Backtrace` 的 `status()` 可能是 `Disabled`/`Captured`
- 回溯输出**不稳定**（地址、帧数量随版本/平台变化），只适合人看
- 错误结构里可以存 `Backtrace`；生态里 `color-eyre`/`anyhow` 提供更友好的报告

### 27.6 日志与诊断生态

| 工具 | 用途 |
|---|---|
| `log` + `env_logger` | 分级日志（error/warn/info/debug/trace） |
| `tracing` + `tracing-subscriber` | 结构化日志、span、异步上下文 |
| `color-eyre` | 彩色错误报告 + 回溯 |
| `cargo clippy` | 静态诊断（含 `dbg_macro` 等 lint） |
| `rust-gdb`/`lldb`/`rr` | 断点调试 |

- 库代码不要 `println!` 输出日志；用 `log`/`tracing`
- `dbg!` 只适合临时排查，提交前删掉
- 结构化日志比字符串拼接更容易检索/聚合

### 27.7 调试工作流

1. 先稳定复现（最小输入、固定环境）
2. 用 `dbg!`/`assert!` 缩小范围（临时）
3. 打开 `RUST_BACKTRACE=1` 看调用路径
4. 用测试固化复现，再修
5. 修完删除临时 `dbg!`，跑 `cargo test`/`clippy`

## 二、具体语法

### 28.1 `dbg!`

```rust
let value = 10;
let doubled = dbg!(value * 2) + 1;

let owned = String::from("x");
dbg!(&owned);          // 只借用
// dbg!(owned);        // 会移动 owned
```

- 表达式只求值一次，返回值可直接参与运算
- 多个表达式可以分别 `dbg!`，避免一次打印巨大结构
- 输出到 stderr；测试里加 `-- --nocapture`

### 28.2 `Debug` 派生与美化

```rust
#[derive(Debug)]
struct User { name: String, age: u32 }

println!("{:?}", user);
println!("{:#?}", user);
```

- `{:?}` 单行、紧凑
- `{:#?}` 多行、缩进
- 枚举会打印变体名与负载：`Some(3)`、`Ok(5)`

### 28.3 自定义 `Debug`

```rust
impl fmt::Debug for Credentials {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        f.debug_struct("Credentials")
            .field("user", &self.user)
            .field("token", &"***")
            .finish()
    }
}
```

- 敏感字段脱敏
- 只打印关键字段
- `finish_non_exhaustive()` 表示"还有未列出的字段"

### 28.4 断言家族

```rust
assert!(value > 0, "value must be positive: {value}");
assert_eq!(add(2, 3), 5);
assert_ne!(add(2, 3), 6);
```

- `assert_eq!` 失败时打印两边，排查最快
- 自定义类型要 `derive(Debug, PartialEq)`
- 浮点用误差范围，不要直接相等

### 28.5 `debug_assert!` 与 `cfg!`

```rust
debug_assert!(index < values.len());

if cfg!(debug_assertions) {
    println!("debug build");
}
```

- `debug_assert!` 只在 debug 构建执行
- `cfg!(debug_assertions)` 返回 `bool`；`#[cfg(debug_assertions)]` 控制代码包含
- `cargo build --release` 默认关闭 debug assertions

### 28.6 `#[track_caller]`

```rust
#[track_caller]
fn require_positive(value: i32) {
    assert!(value > 0, "must be positive: {value}");
}
```

- panic 位置指向调用者
- 自定义断言/校验函数应加 `#[track_caller]`
- `Location::caller()` 读取调用点

### 28.7 回溯

```rust
let backtrace = std::backtrace::Backtrace::capture();
println!("{:?}", backtrace.status());
```

- 运行前设置 `RUST_BACKTRACE=1`
- `force_capture()` 强制捕获
- 回溯只用于诊断，不要做断言/协议

### 28.8 `log` / `tracing`（外部 crate）

```rust
log::debug!("loading config: {path}");
tracing::info!(port = 8080, "server started");
```

- `log` 是门面，`env_logger` 是后端；`RUST_LOG=debug` 控制级别
- `tracing` 用字段/span 表达结构化上下文
- 库只依赖 `log`/`tracing` 门面，不绑定具体后端

## 三、实际应用与最佳实践

### 29.1 脱敏 Debug

```rust
f.debug_struct("Credentials")
    .field("user", &self.user)
    .field("token", &"***")
    .finish()
```

日志里出现 token/密码/身份证号是常见事故；自定义 `Debug` 是最低成本的防线。

### 29.2 配置校验：诊断信息写进 `Err`

```rust
if config.port == 0 {
    return Err(String::from("port must be non-zero"));
}
```

- 错误消息包含"哪个字段、什么值、期望什么"
- 断言消息包含实际值：`assert!(age <= 150, "age out of range: {age}")`
- 不要只写 `"invalid config"`

### 29.3 断言消息与 `#[track_caller]`

```rust
#[track_caller]
fn assert_valid_port(port: u16) {
    assert!(port >= 1024, "port must be >= 1024, got {port}");
}
```

- 包装断言函数加 `#[track_caller]`，定位到真实调用点
- 断言消息能复现问题，不用再猜

### 29.4 最佳实践清单

1. **`dbg!` 只用于临时排查**，提交前删除
2. **`dbg!(owned)` 会移动**；只看不取用 `dbg!(&owned)`
3. **Debug 给开发者，Display 给用户**
4. **敏感字段自定义 Debug 脱敏**
5. **Debug 输出不是稳定格式**，不要解析/依赖
6. **`assert!` 用于内部不变量**，外部输入用 `Result`
7. **`assert_eq!` 打印两边**，是排查首选
8. **`debug_assert!` 不放必要逻辑**
9. **自定义校验函数加 `#[track_caller]`**
10. **日志用 `log`/`tracing`**，库代码不 `println!`

## 常见陷阱

1. **`dbg!(owned)` 移动所有权**：之后原变量不可用；用 `dbg!(&owned)`
2. **`dbg!` 输出在 stderr**：测试里看不到，需要 `--nocapture`
3. **`dbg!` 打印中文路径/源码**：控制台编码可能乱码；只用于临时调试
4. **提交时忘记删 `dbg!`**：用 clippy 的 `dbg_macro` lint 拦截
5. **`derive(Debug)` 泄露密码/token**：日志、panic、错误链都会打印
6. **解析 Debug 输出**：格式不稳定，升级 Rust 可能变
7. **`assert_eq!` 缺 `Debug`**：自定义类型要 `derive(Debug, PartialEq)`
8. **用 `assert!` 校验用户输入**：生产环境 panic；返回 `Result`
9. **`debug_assert!` 的副作用在 release 消失**：不要把初始化/校验逻辑放进去
10. **`debug_assert!` 当业务校验**：release 不执行，安全漏洞
11. **包装断言函数漏 `#[track_caller]`**：panic 位置指向包装函数内部
12. **回溯没开**：`RUST_BACKTRACE=1` 才打印；`Backtrace::status` 可能是 Disabled
13. **把回溯当地址/协议**：地址和帧数都不可靠
14. **Debug 打印超大结构**：日志爆炸；只打印关键字段/摘要
15. **Debug 实现里有副作用/panic**：日志代码把程序搞挂；保持简单
16. **库代码 `println!`**：污染调用方 stdout；用 `log`
17. **热循环里 `eprintln!`/`dbg!`**：IO 成为瓶颈
18. **自定义 panic hook 覆盖默认信息**：确保仍记录 payload/location
19. **错误 `Debug` 打印敏感上下文**：上报系统可能全文收集
20. **断言消息没有实际值**：只写 "failed"，排查还得重跑

## 完整示例

见 `27_debugging_and_assertions.rs`，按 **① 原理验证 → ② 语法演示 → ③ 应用实战**
三段组织，先预测输出再运行（示例输出刻意只用 ASCII，规避 Windows 控制台编码问题）：

```bash
rustc --edition 2024 -D warnings "ERRORS/27_调试与诊断/27_debugging_and_assertions.rs" -o run.exe
./run.exe
```

示例共 17 行输出，覆盖：`derive(Debug)`、`{:#?}` 美化、自定义 Debug 脱敏、
`assert_eq!` 的失败消息、`cfg!(debug_assertions)`、`debug_assert!`、
`finish_non_exhaustive`、配置校验与带实际值的断言消息。

> 说明：`dbg!` 输出到 stderr 且带源码路径，示例为保持 stdout 可预测没有直接调用；
> 它的展开与典型输出见 27.1/28.1。

## 练习

1. 给一个结构体 `derive(Debug)`，分别用 `{:?}` 与 `{:#?}` 打印。
2. 自定义 `Debug` 给密码/token 字段脱敏，并验证日志里看不到原文。
3. 用 `catch_unwind` 捕获 `assert_eq!(3, 4)`，打印 panic 消息并解释左右对齐。
4. 写一个 `#[track_caller]` 的端口校验函数，触发 panic 并观察位置。
5. 用 `debug_assert!` 检查数组索引，分别用 debug 与 release 运行，比较行为。
6. 设置 `RUST_BACKTRACE=1` 触发 panic，观察回溯；再用 `Backtrace::capture` 打印状态。
7. 写一段 `dbg!(owned_string)` 的代码，解释为什么之后不能再用原变量；改成 `dbg!(&owned)`。
8. 用 `log`/`tracing` 的写法替换一段 `println!` 日志（只写代码，不需要本机编译）。
