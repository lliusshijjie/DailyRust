# 第 24 课 · 自定义错误类型与错误链

> 所需工具链：rustc 1.85+（edition 2024） ｜ 讲解：本文件 ｜ 独立代码：`24_custom_errors_and_chains.rs`

## 一、底层原理

### 24.1 `std::error::Error` 的契约

```rust
pub trait Error: Debug + Display {
    fn source(&self) -> Option<&(dyn Error + 'static)> { None }
    // ... 其余方法有默认实现
}
```

实现自定义错误类型需要：

1. `Debug`：开发者视角（`{:?}`），通常 `#[derive(Debug)]`
2. `Display`：用户视角（`{}`），手写可读消息
3. `Error`：提供 `source()` 指向根因（可选）

`source()` 返回的是 `&(dyn Error + 'static)`，所以错误链里的每一层都必须是
`'static`（不能借用局部数据）。`Error` 是对象安全的，可以放进
`Box<dyn Error>`、`&dyn Error`。

`Display` 与 `Debug` 的分工：

| 用途 | trait | 内容 |
|---|---|---|
| 用户/日志 | `Display` | 简洁、可读、无内部细节 |
| 开发者/断言 | `Debug` | 字段、类型、上下文 |

### 24.2 自定义错误枚举

库/模块的错误推荐用**枚举**，每个变体一种失败：

```rust
#[derive(Debug)]
enum ConfigError {
    MissingHost,
    MissingPort,
    InvalidPort(ParseIntError),
}

impl fmt::Display for ConfigError { ... }
impl Error for ConfigError {
    fn source(&self) -> Option<&(dyn Error + 'static)> {
        match self {
            ConfigError::InvalidPort(source) => Some(source),
            _ => None,
        }
    }
}
```

- 枚举让调用方可以 `match` 具体失败，做差异化处理
- 每个变体可以携带上下文（字段名、非法值、路径）
- `source()` 保留根因，`Display` 只写本层信息，两者配合形成错误链
- 公开错误枚举建议加 `#[non_exhaustive]`，以后新增变体不破坏下游

### 24.3 错误链：上下文 + 根因

真实错误往往是分层的：

```
LoadError: failed to load config.txt
└── ConfigError: invalid port
    └── ParseIntError: invalid digit found in string
```

实现方式：

- 外层错误持有内层错误作为 `source` 字段
- `Display` 写"本层发生了什么"，`source()` 返回内层
- 遍历 `source()` 就能打印完整链

```rust
fn chain(error: &dyn Error) -> Vec<String> {
    let mut messages = vec![error.to_string()];
    let mut current = error.source();
    while let Some(source) = current {
        messages.push(source.to_string());
        current = source.source();
    }
    messages
}
```

注意：`source()` 不能返回自己（否则链遍历死循环），也不能返回借用局部数据的错误。

### 24.4 `?` 与 `From`：错误转换的桥梁

`?` 在 `Err` 时调用 `From::from` 把源错误转成函数返回类型：

```rust
impl From<ParseIntError> for ConfigError {
    fn from(error: ParseIntError) -> Self {
        ConfigError::InvalidPort(error)
    }
}

fn parse_port(text: &str) -> Result<u16, ConfigError> {
    let port: u16 = text.parse()?;   // ParseIntError -> ConfigError
    Ok(port)
}
```

规则：

- 一个源错误类型只能对应一个 `From` 目标；同一 `ParseIntError` 想落到两个变体时，
  用 `map_err` 显式选择
- 没有 `From` 时用 `map_err` 添加上下文
- `From` 实现要保留源错误，而不是只留字符串

### 24.5 库错误 vs 应用错误

| 层 | 推荐 | 原因 |
|---|---|---|
| 库 | 具体错误枚举（`thiserror`） | 调用方可以 `match`，语义稳定 |
| 应用 | `anyhow::Error` / `Box<dyn Error>` | 需要上下文、快速传播，不要求匹配 |
| 入口/CLI | `anyhow` + `Context` | 打印完整链、用户友好 |

`thiserror` 用 derive 生成 `Display`/`Error`/`From`：

```rust
#[derive(thiserror::Error, Debug)]
enum ConfigError {
    #[error("missing host")]
    MissingHost,
    #[error("invalid port")]
    InvalidPort(#[from] ParseIntError),
}
```

`anyhow` 给应用层错误加上下文：

```rust
use anyhow::{Context, Result};

fn load() -> Result<()> {
    let text = std::fs::read_to_string("app.conf").context("read config")?;
    ...
}
```

两者都不是标准库；本课示例用标准库手写等价实现。

### 24.6 `Box<dyn Error>` 与 downcast

`Box<dyn Error>` 可以装任何 `Error + 'static` 的具体错误：

```rust
impl<E: Error + 'static> From<E> for Box<dyn Error> { ... }
```

- 适合混合错误源、入口函数
- 丢失具体类型，需要分支处理时用 `downcast_ref::<T>()` 或 `downcast::<T>()`
- 跨线程/异步用 `Box<dyn Error + Send + Sync + 'static>`
- 需要 `match` 时优先自定义枚举，而不是向下转型

### 24.7 错误类型的设计要求

- `Debug` + `Display` + `Error`
- 保留 `source`，不要丢根因
- `Display` 写"发生了什么"，不要泄露密码/密钥
- 错误枚举 `#[non_exhaustive]`（公开 API）
- 跨线程错误要 `Send + Sync + 'static`
- 错误类型尽量小；大字段可以 `Box` 起来
- 错误链不要形成环
- 库函数不要 `unwrap`/`panic`，把错误交给调用方

## 二、具体语法

### 25.1 定义错误枚举

```rust
#[derive(Debug)]
#[non_exhaustive]
pub enum ConfigError {
    MissingHost,
    InvalidPort { value: String, source: ParseIntError },
}
```

- 变体名用名词/过去分词（`MissingHost`、`InvalidPort`）
- 字段放上下文（`value`、`path`、`line`）
- `#[non_exhaustive]` 只对公开枚举有意义

### 25.2 实现 `Display` 与 `Error`

```rust
impl fmt::Display for ConfigError {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            ConfigError::MissingHost => write!(f, "missing host"),
            ConfigError::InvalidPort { value, .. } => write!(f, "invalid port `{value}`"),
        }
    }
}

impl Error for ConfigError {
    fn source(&self) -> Option<&(dyn Error + 'static)> {
        match self {
            ConfigError::InvalidPort { source, .. } => Some(source),
            _ => None,
        }
    }
}
```

- `Display` 不要带换行/句号（标准库风格）
- `source` 返回内层错误的引用
- 没有内层错误时返回 `None`（默认实现就是 `None`）

### 25.3 `From` 转换

```rust
impl From<ParseIntError> for ConfigError {
    fn from(error: ParseIntError) -> Self {
        ConfigError::InvalidPort(error)
    }
}
```

- 为每个常见源错误实现 `From`
- 同名源错误只能映射到一个变体；多个变体用 `map_err`
- `thiserror` 的 `#[from]` 会自动生成这段代码

### 25.4 链式上下文

```rust
#[derive(Debug)]
struct LoadError {
    path: String,
    source: ConfigError,
}

impl fmt::Display for LoadError {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        write!(f, "failed to load {}", self.path)
    }
}

impl Error for LoadError {
    fn source(&self) -> Option<&(dyn Error + 'static)> {
        Some(&self.source)
    }
}
```

- 外层错误只写本层上下文，根因通过 `source` 传递
- 遍历 `source()` 打印完整链

### 25.5 `Box<dyn Error>`

```rust
fn main() -> Result<(), Box<dyn Error>> {
    let port: u16 = "8080".parse()?;
    println!("{}", port);
    Ok(())
}

let boxed: Box<dyn Error + Send + Sync> = Box::new(ConfigError::MissingPort);
boxed.downcast_ref::<ConfigError>();
```

- `?` 会自动把 `E: Error + 'static` 装箱
- `downcast_ref` 取回具体类型；`downcast` 消耗 Box
- 跨线程/异步要加 `Send + Sync`

### 25.6 `thiserror` / `anyhow`（工程实践）

```rust
// 库：具体错误枚举
#[derive(thiserror::Error, Debug)]
pub enum DbError {
    #[error("connection failed")]
    Connection(#[from] std::io::Error),
    #[error("user {0} not found")]
    NotFound(u64),
}

// 应用：上下文 + 传播
use anyhow::{Context, Result};

fn run() -> Result<()> {
    let text = std::fs::read_to_string("app.conf").context("read config")?;
    Ok(())
}
```

- `thiserror` 适合库：错误类型可匹配、`Display`/`From` 自动生成
- `anyhow` 适合应用：`.context(...)` 添加上下文，统一 `anyhow::Error`
- 两者可组合：库用 `thiserror`，应用用 `anyhow`

### 25.7 `#[non_exhaustive]`

```rust
#[non_exhaustive]
pub enum ApiError {
    NotFound,
    Forbidden,
}
```

- 定义 crate 内部仍可穷尽匹配
- 下游必须写 `_`，为以后新增变体留空间

## 三、实际应用与最佳实践

### 26.1 配置加载：三层错误链

```rust
let load_error = load("config.txt", "host=localhost\nport=x").unwrap_err();
println!("{}", load_error);                 // failed to load config.txt
chain(&load_error);                         // [LoadError, ConfigError, ParseIntError]
```

`LoadError` 提供"在哪个文件失败"，`ConfigError` 提供"哪个字段失败"，
`ParseIntError` 提供"为什么失败"。日志里打印整条链，排查最快。

### 26.2 API 错误枚举：让调用方可匹配

```rust
match api_call() {
    Err(ApiError::NotFound(id)) => ...,
    Err(ApiError::Forbidden) => ...,
    Ok(value) => ...,
}
```

库的公开错误应该是**可匹配的枚举**；`Box<dyn Error>` 适合入口层，
不适合库契约。

### 26.3 库/应用分层

- 库：`thiserror` 枚举 + `source` 链；不要 `unwrap`
- 应用：`anyhow` + `Context`；在最外层打印链
- CLI：`anyhow` 的错误链 + 非零退出码
- 异步/线程：错误必须 `Send + Sync + 'static`

### 26.4 最佳实践清单

1. **自定义错误要 `Debug + Display + Error`**
2. **`Display` 写本层，`source` 传根因**
3. **错误枚举携带上下文**（字段、值、路径、行号）
4. **用 `From` 让 `?` 自动转换**，保留源错误
5. **公开错误枚举加 `#[non_exhaustive]`**
6. **库用具体枚举，应用用 `anyhow`/`Box<dyn Error>`**
7. **`Display` 不泄露敏感信息**
8. **跨线程错误加 `Send + Sync`**
9. **不要 `unwrap`/`panic` 处理可恢复错误**
10. **错误链不要成环，也不要丢掉根因**

## 常见陷阱

1. **只实现 `Debug` 没实现 `Display`（E0277）**：`Error` 要求 `Display`；
   手写或 `thiserror`
2. **只存字符串、不存 `source`**：丢失根因，无法打印错误链
3. **`source` 借用局部数据**：`source` 要求 `'static`；错误里存拥有所有权的数据
4. **两个变体都包装同一种源错误**：`?` 无法决定用哪个 `From`；用 `map_err`
5. **`Box<dyn Error>` 后想 `match` 具体错误**：类型已擦除；用 `downcast_ref`
   或直接返回枚举
6. **`Display` 太模糊**：只写 "error" 无法定位；写清字段/值/位置
7. **`Debug` 泄露密码/令牌**：日志可能记录 `{:?}`；敏感字段要脱敏
8. **公开错误枚举没加 `#[non_exhaustive]`**：新增变体破坏下游 `match`
9. **跨线程用非 `Send` 错误**：`Box<dyn Error + Send + Sync>` 编译失败
10. **`source()` 返回 `self`**：链遍历死循环
11. **错误链循环引用**：`A.source = B`、`B.source = A` 会无限循环
12. **`thiserror` 的 `#[from]` 重复**：同一源错误只能有一个 `#[from]`
13. **库用 `anyhow` 作为公开错误**：调用方无法匹配具体错误
14. **`unwrap` 处理外部输入**：生产代码应传播错误
15. **把 panic 当错误处理**：可恢复错误用 `Result`，不可恢复才 panic
16. **错误类型不是 `'static`**：带借用的错误不能进 `Box<dyn Error>`
17. **`Box<dyn Error>` 没加 `Send + Sync` 就跨线程**：编译失败
18. **错误消息带句号/大写开头不一致**：风格不统一；标准库风格是小写、无句号
19. **忘记实现 `Error` 就 `?` 进 `Box<dyn Error>`**：E0277
20. **错误枚举过大**：大字段建议 `Box`，避免 `Result` 变大

## 练习

1. 定义 `ConfigError` 枚举（缺少 host/port、端口非法），实现 `Display` 与 `Error`。
2. 实现 `LoadError { path, source }`，遍历并打印三层错误链。
3. 为 `ParseIntError` 和 `std::io::Error` 各写一个 `From`，在同一个函数里用 `?`。
4. 用 `Box<dyn Error>` 装一个自定义错误，再 `downcast_ref` 回具体类型。
5. 给错误枚举加 `#[non_exhaustive]`，说明为什么公开 API 需要它。
6. 用 `thiserror` 的写法重写练习 1（只写代码，不要求在本机编译）。
7. 用 `anyhow` 的 `.context()` 给一个 IO 操作添加上下文（同样只写代码）。
8. 设计一个 `ApiError` 枚举，让调用方可以分别处理 NotFound/Forbidden/Invalid，
   并保留底层 `source`。
